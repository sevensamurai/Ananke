# Ananke v0.8.4

**Theme: platform review loops and studio scaffolding — richer Slack integrations, reusable review and budget gates, async review parking, Slack role-binding helpers, and a practical mini-agency demo.**

No breaking changes are intended in this release. The changes are additive: new platform events and response helpers, new Organics review and budget abstractions, async review parking, a new `Ananke.Roles` package with Slack binding helpers, optional OpenTelemetry-backed budget metering, and a Slack-backed demo that ties the pieces together.

## What's new

### Slack platform catch-up

`Ananke.Platforms` and `Ananke.Platforms.Slack` now expose the key primitives needed for lightweight human-in-the-loop review flows on Slack:

- `PlatformReactionEvent` added to normalize inbound reaction events across platforms.
- `IPlatformMessageHandler` now has `OnReactionAsync(...)`, so adapters can dispatch reactions without forcing every implementation to change.
- Slack adapter registration now supports `app_mention` and `reaction_added` events.
- `SlackMessageMapper` now maps both app mentions and reactions into the normalized platform model.
- `ISlackResponseSink` adds Slack-native response operations beyond plain message send/update:
  - Block Kit messages
  - ephemeral messages
  - external file uploads
  - scheduled messages

Together, these additions make Slack a more complete execution surface for multi-step agent workflows and approval loops.

### Work-review and budget gates in Organics

`Ananke.Organics` gains a reusable review layer for work products plus a rolling-window budget meter:

- `IWorkReviewGate` and supporting review models:
  - `WorkItem`
  - `WorkItemKind`
  - `WorkReviewDecision`
  - `WorkReviewOutcome`
  - `WorkReviewQuorum`
- Built-in review gate implementations:
  - `AutoWorkReviewGate`
  - `CallbackWorkReviewGate`
  - `LlmWorkReviewGate`
  - `QuorumWorkReviewGate`
- Budget abstractions and in-memory implementation:
  - `IBudgetMeter`
  - `BudgetSpend`
  - `InMemoryBudgetMeter`
  - `BudgetApprovalGate`

This gives hosts a generic way to combine automated review, human callbacks, quorum rules, and token-cap enforcement without hard-coding policy into application logic.

### `Ananke.Roles` — persona and studio host scaffolding

A new `Ananke.Roles` package introduces reusable role definitions and studio-oriented host wiring:

- `AgentRole`, `ReviewPolicy`, and `EscalationPolicy` define role behavior declaratively.
- `IAgentRoleCatalog` and `AgentRoleCatalog` provide lookup and registration.
- `RoleManifestFactory` projects roles into `WorkflowManifest` definitions.
- `StudioOptions`, `StudioRouter`, and `StudioHostBuilder` wire roles and workflows into a host-friendly composition surface.

This layer is intended for applications that want persona-driven workflow selection and manifest generation without coupling those concerns directly into the core orchestration packages.

### Optional OpenTelemetry budget meter

`Ananke.OpenTelemetry` now includes `OpenTelemetryBudgetMeter`, an `IBudgetMeter` implementation backed by federation-style counters:

- `ananke.federation.tokens.in`
- `ananke.federation.tokens.out`
- `ananke.federation.usd`

`TracingExtensions.AddBudgetMeter(...)` registers the listener-backed meter with configurable rolling windows and per-role caps. Budget enforcement still works without telemetry through `InMemoryBudgetMeter`; OpenTelemetry is an optional integration path rather than a requirement.

### `MiniAgencyDemo` application

A new demo at `src/demos/05-applications/MiniAgencyDemo` shows how the new pieces fit together in a realistic application:

- Slack-backed runtime using `AddAnankeSlack(...)`
- drafter and reviewer roles loaded from `roles.json`
- local OpenAI-compatible model configuration via environment variables
- draft → review → Slack reaction approval flow
- in-memory budget enforcement by default
- optional emission of federation-style metrics when enabled

The demo is intentionally practical: the runtime orchestration is implemented in a custom platform message handler, while the role and workflow artifacts are still wired through the studio layer.

### Test coverage and docs

This release also adds focused tests and documentation for the new slices:

- Organics tests for review gates, quorum behavior, budget metering, parking store, and parking gate
- Roles tests for catalogs, manifest generation, router behavior, host wiring, channel map, role-aware handler, and approval callback
- OpenTelemetry tests for budget meter rollover and DI registration
- updated architecture and README docs in all touched packages

### Slack inbound: slash commands and interactivity

`Ananke.Platforms` and `Ananke.Platforms.Slack` add normalised inbound support for the review-workflow interaction surfaces:

- `PlatformSlashCommand` record normalises slash-command payloads (`Command`, `Text`, `UserId`, `ChannelId`, `TriggerId`).
- `PlatformInteractionEvent` record normalises block-action and view-submission payloads (`ActionId`, `Value`, `TriggerId`, `UserId`, `ChannelId`, `ThreadId`, `Kind`).
- `IPlatformMessageHandler` gains default no-op hooks: `OnSlashCommandAsync` and `OnInteractionAsync`.
- `SlackAdapterOptions` gains `EnableSlashCommands` and `EnableInteractivity` (both default `false`).
- Events API mode: `MapAnankeSlackEvents()` exposes `/slack/events`, `/slack/commands`, and `/slack/interactivity` with signing-secret validation.

### Slack inbound: Assistant pane

First-class support for Slack's Agents & AI Apps Assistant pane:

- `PlatformAssistantThreadEvent` normalises thread-started and context-changed events.
- `IPlatformMessageHandler.OnAssistantThreadAsync(...)` default no-op hook.
- `ISlackResponseSink` gains `SetAssistantStatusAsync` and `SetSuggestedPromptsAsync`.
- `SlackAdapterOptions` gains `EnableAssistant` and `AssistantStatusLabel`.

### Slack outbound: modals, message metadata, upload mode

- `ISlackResponseSink.OpenViewAsync` / `UpdateViewAsync` for modal dialogs.
- `SlackApprovalBlocks.Build(workItem)` — Block Kit Approve / Revise / Reject layout with canonical action ids.
- Optional metadata footer on `chat.postMessage` for traceability.
- `SlackUploadMode` toggle: `ExternalUrlV2` (default, with `expired_url` retry) or `LegacyFilesUpload`.

### Slack role-binding helpers in `Ananke.Roles`

The new `Ananke.Roles.Slack` sub-namespace bridges Slack channels and interactions to the role layer:

- `SlackChannelMap` — typed wrapper around `StudioOptions.ChannelRoleMap`, resolves a channel id to an `AgentRole`.
- `RoleAwareMessageHandler` — routes each `PlatformMessage` to the workflow named after the resolved role, with configurable fallback.
- `SlackApprovalCallback` — translates block-action interactions into `WorkReviewDecision` values for `CallbackWorkReviewGate`.

### Async review parking

Parking pattern for human-in-the-loop review flows where a decision may arrive hours later:

- `IWorkReviewParkingStore` — store interface (`ParkAsync`, `TryGetAsync`, `CompleteAsync`). Default: `InMemoryWorkReviewParkingStore`.
- `ParkingCallbackWorkReviewGate` — parks on `ReviewAsync`, returns `WorkReviewOutcome.Pending` immediately with the parking id in the `Comment` field, resolves via `ResumeAsync(parkingId, decision)`.

### Platform review notification helper

`Ananke.Platforms` gains a transport-neutral helper for surfacing work items to reviewers:

- `WorkItemReviewNotifier` — accepts an `IPlatformResponseSink` and primitive work-item fields, posts a formatted "please review" notification to the configured channel/thread.
- Opts out cleanly when no channel is configured (returns `null` without calling the sink).
- Platform-specific rendering (e.g. Block Kit approval buttons) remains the sink's responsibility, keeping the helper free of Slack or any other platform dependency.
- `WorkReviewOutcome.Pending` added.
