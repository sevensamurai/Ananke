# Ananke v0.9.2

**Theme: reliable when several servers share Redis and MQTT, and the packages tested as you install them**

## In short

- **Several servers, one state.** State machines, locks and stored values now behave correctly when more than one
  server shares the same Redis, and keep working through a Redis or MQTT outage instead of quietly losing state.
- **Secure connections.** Redis connects with a user name, password and TLS; MQTT connects over TLS and reconnects
  on its own after the broker comes back.
- **Lighter Redis package.** `Ananke.Redis` no longer pulls in the AI packages. The Redis checkpoint store is
  replaced by `KeyValueCheckpointStore`, which works over the key-value adapter `AddRedis` registers.
- **Better document search.** Postgres keyword search ranks results the standard way (BM25), filters can match one
  of several values, results show their date and what replaced them, and documents can link to each other.
- **Current AI models.** GPT-6 and Gemini 4 are added; OpenAI models that were shut down are removed.
- **Fixes.** Spending limits now count the cost a provider reports, the context limit holds on the last call of a
  turn, cached replies respect the output limit, and long streamed replies are no longer cut off early.
- **Tested as shipped.** Every package is built and checked the way you install it, and all Ananke packages must be
  the same version.

## Before you upgrade

Most of this release changes behaviour. Check these first; each is explained under *Upgrading* and *Breaking
changes* below.

1. **State machine data moves to new keys.** Records saved by 0.9.1 are not found after the upgrade unless you set
   `KeyPrefix` and `MachineName` to `""` or copy the records.
2. **Store failures now fail.** When Redis is down, transitions and reads report an error instead of carrying on as
   if nothing was stored. Handle or retry these errors.
3. **Using `RedisCheckpointStore`?** Replace it with `KeyValueCheckpointStore`; nothing else changes.
4. **Reading a state machine's current state?** The instance properties are gone; call `GetStatusAsync(context)`.
5. **Model ids.** Retired OpenAI model constants are removed, and old model names in your code now give build
   warnings (errors if warnings are treated as errors).
6. **Postgres search.** Keyword results are ranked differently, and the first start on an existing table creates
   extra tables and triggers, so the database role needs the rights to do that. Listing by date needs PostgreSQL 16.
7. **MQTT settings.** If you read `IOptions<ChannelConfig>` after `AddMqtt`, read the named options instead.

## Fixes

- A spending limit and the cost metrics now include the cost a provider reports itself (such as OpenRouter's).
- The context limit is now enforced on the final call of a turn, too.
- The response cache keeps replies with different output limits apart. Entries cached by 0.9.1 are not reused.
- `CachingAgentModel` now stores each reply with its `ttl` as the key's expiry, so Redis (or the in-memory store) drops
  expired replies itself instead of keeping them until they are read again.
- A repeated reply or a timeout is never retried, even when its message mentions a wait.
- A long streamed reply is only stopped early when it repeats a very long passage.

## What's new

### State machine
- **Status per context.** `AbstractStateMachine.GetStatusAsync(context, ct)` returns a `ContextStatus<S>`
  (`State`, `Step`, `OperationalStatus`, `OperationalStatusReason`, `IsInterrupted`) read from the store, so every
  node sees the same answer for a context.
- **Store keys per machine.** `StateMachineOptions.KeyPrefix` (default `"statemachine"`) and `MachineName` (default the
  machine's type name) make a context's store key and lock resource `{KeyPrefix}:{MachineName}:{context.Id}`;
  `AbstractStateMachine.MachineName` and `GetContextKey(id)` give them. A record stores `PersistedContext.Version`
  (`FormatVersion` = 1); a record without one reads as 0 and is accepted, a higher one is refused.
- **`TransitionResult.StateStored`**: true when this attempt wrote a record — every success, and a failure after the
  write.
- **Cancellation.** `TransitionAsync`, `NotifyAsync`, `InternalTransitionAsync` and `IQueryableStateMachine.GetStateAsync`
  take a `CancellationToken`; `StateMachineChannelWorker` and the Bridge jobs pass theirs.

### Redis: `Ananke.Redis`
- **`KeyValueCheckpointStore`** (in `Ananke.Orchestration`) replaces `RedisCheckpointStore`: it keeps one JSON string
  per execution in any `IKeyValueDataAdapter`, such as the one `AddRedis` registers. `Ananke.Redis` keeps `AddRedis`,
  the lock, the key-value adapter and `RedisConversationMemory`, and depends on `Ananke.Abstractions` only.
- **`CacheConfig`** gains `Ssl` (TLS), `ConnectionString` (StackExchange.Redis format; it wins over `Host`, `Port`,
  `Username`, `Password` and `Ssl`), `Database` (null: the connection's default) and `KeyPrefix` (before every value
  key and lock name; lock keys are `{KeyPrefix}redlock:{resource}`). `Username` now reaches the connection.
- **The first connect** makes one attempt unless the connection string sets `connectRetry` (StackExchange.Redis's
  default is three), so `CacheConfig.ConnectTimeoutMs` bounds it; an operation's token ends its wait for it.
- **One connection.** `AddRedis` uses an `IConnectionMultiplexer` the host registers (before or after it) for values
  and locks and opens no other; the host keeps owning it. `RedisDataAdapter` and `RedisDistributedLock` take one as an
  optional third constructor parameter.
- **Values that expire.** `IKeyValueDataAdapter.SetValueAsync(key, value, TimeSpan? expiry, ct)` and its generic twin,
  in Redis and in `InMemoryDistributedLock`, which also takes an optional `TimeProvider` and removes a value that has
  expired on the next write, whether or not it was read.
- **`RedisDataAdapter` honours its `CancellationToken`** while a command waits for the server: get, set, remove and
  exists throw `OperationCanceledException` when the token is cancelled, rather than waiting for `AsyncTimeoutMs`. A
  command already sent keeps running, so a cancelled set or remove may still take effect.
- `KeyValueCheckpointStore` and `RedisConversationMemory` honour their `CancellationToken` on every operation, and
  `RedisConversationMemory` with a ttl appends and sets the expiry in one `MULTI`/`EXEC` transaction.

### MQTT
- **`ChannelConfig`** gains `UseTls` (the broker's certificate validated against the machine's trusted roots; set
  `Port`, commonly 8883), `ClientId` (each client's id is the value cut to 14 characters, `-` and 8 hex digits of a
  hash of the whole value, the client's role, types, namespace and, for a handoff channel, its new `Name`: at most 23
  characters and the same after a restart; a second channel with an id already in use in the process throws
  `InvalidOperationException`), `CleanSession` (default true; false needs a `ClientId`, asks for a session that never
  expires, and a reader's dispose then leaves its topic subscribed) and `QualityOfService` (`ChannelQualityOfService`,
  default `ExactlyOnce`, for publishes and subscriptions).
- **Reconnects.** The reader, the writer and the handoff channel retry a lost connection without a limit until
  disposed (reader and writer: or `ClearAsync`), one attempt per delay of 1 s doubling to 30 s, and resubscribe on
  every connect. The retries start even when the first `ConfigureAsync` connect fails (it still returns false).
  `MqttChannelReader.IsConnected` means connected and subscribed: after a reconnect it is false until the topic is
  subscribed again.
- **A payload that can't be read** is logged and dropped, and the next message is delivered.

### Background processing
- **`BackgroundProcessor.CompleteAsync(ct)`**, on both processors, refuses new items (`TryEnqueue` returns false,
  `EnqueueAsync` throws `ChannelClosedException`) and returns once every queued item was handled. It starts the loop
  if not started, and throws `OperationCanceledException` if the loop is stopped (the `Start` token, `DisposeAsync`)
  before the queue drains. The worker must not call `CompleteAsync` or `DisposeAsync`: they wait for its own loop.
- `CachingAgentModel` takes an optional `ILogger` (last constructor parameter, `logger`). A cache that throws on read
  or write never fails the call: the read is a miss, the response is returned unstored, and each failure is logged as
  a warning.

### Analyzers a product gets
- **ANNKE002 and ANNKE003 from the package, with no setup.** A product referencing `Ananke.Orchestration` gets
  ANNKE002 (deprecated model id literal, warning) and ANNKE003 (retired, error): `model-lifecycle.json` is embedded in
  the analyzer, and a file named `model-lifecycle.json` given as `AdditionalFiles` replaces it. The code fix (replace
  the literal with the `Models.*` constant, one site at a time) is packed too.
- The analyzer ids a product sees: `ANANKE001` (undefined job name), `ANNKE001` (compiler, the `[Obsolete]` `Models`
  constants), `ANNKE002`, `ANNKE003`.

### Models
- **GPT-6 and Gemini 4.** New `Models.OpenAI` constants `Gpt6Sol`, `Gpt6Luna`, `Gpt6Astra`, `Gpt61Sol`, `Gpt61Terra`,
  `Gpt62Sol`, `Gpt62Astra`, and `Models.Google` constants `Gemini38Flash`, `Gemini4Carbon`, `Gemini4Argon`,
  `Gemini4Hydrogen`, each in both `ModelCatalog`s. The starred models are unchanged.

### Knowledge
- **A filter key with several values.** `KnowledgeFilter.AnyOf` (experimental: `ANNKEEXP004`) holds keys a document
  matches when its value is any of those given, as in `AnyOf = { ["outlet"] = ["TechCrunch", "The Verge"] }`. The
  in-memory, Postgres and Qdrant stores apply it in search, listing and delete; the scoped, catalog-aware and linked
  stores pass it on. One value per key works as before.
- **The documents a document links to.** `DocumentProcessor.Hyperlinks` (`HyperlinkOptions`, experimental:
  `ANNKEEXP004`) writes each hyperlink of a section that resolves to a source id into the metadata of that section's
  chunks as `entity:document:{source id}`; relative links resolve against the document's own source id by default,
  external URLs are left out. With it set, the chunker is given one section at a time. `LinkedDocumentReader` lists
  the documents a source links to, newest first, with each one's date and what supersedes it, and
  `KnowledgeCatalogTools.CreateLinks` gives agents a `list_linked_documents` tool. Off unless set.
- **Search results say their date and what supersedes them.** `CatalogAwareKnowledgeStore.SearchAsync` sets each
  result's `effective_at` and `superseded_by` from its catalog entry when the chunk lacks them, and `search_knowledge`
  prints `Date:` and `Superseded by:` lines. The ranking is unchanged by default;
  `CatalogAwareKnowledgeStore.SupersededResults` (enum `SupersededResults` in `Ananke.Orchestration.Knowledge.Catalog`,
  experimental: `ANNKEEXP004`: `Mark`, the default, `Demote`, `Exclude`) changes it. Under `Exclude` a search can ask
  the store again, doubling `TopK` up to 16 times it, until it has `TopK` current results.
- **Lists ordered by date in the store.** `IListableKnowledgeStore.ListAsync` takes a `KnowledgeDateOrder? order`
  (new record `KnowledgeDateOrder(Key, Since)`, experimental: `ANNKEEXP004`): newest first by that key, bounded below
  by `Since`, applied in each store's query instead of after a cut.
- **Postgres dense search returns the rows asked.** New `PostgresKnowledgeOptions.HnswEfSearch` (default 40) and
  `HnswIterativeScan` (enum `PostgresIterativeScan`, default `StrictOrder`), both experimental: `ANNKEEXP004`.
- **Postgres keyword search by BM25.** New `PostgresKnowledgeOptions.RareTermShare` (default 0.05, experimental:
  `ANNKEEXP004`).

## Upgrading

### State machine
- ⚠ **A fault covers one context.** `FaultAsync(device-1)` no longer stops the other contexts on the same instance,
  and does stop device-1 on every instance over the same store, until `ResetAsync`. Fault and reset take the context's
  lock and throw `TimeoutException` when it can't be acquired.
- ⚠ **Store keys change.** Store keys and lock resources are `{KeyPrefix}:{MachineName}:{context.Id}` (by default
  `statemachine:<machine type name>:<id>`) instead of the bare id, so records written by 0.9.1 are not read after
  the upgrade. To keep reading them, set `StateMachineOptions.KeyPrefix = ""` and `MachineName = ""` (an empty part is
  left out; both empty give the bare id), or copy each record to `machine.GetContextKey(id)` before starting.
- ⚠ **A failed store fails the transition.** With the store failing, a transition returns `Success = false` with the
  store's exception and writes nothing, instead of starting the context at the initial state; `FaultAsync` and
  `ResetAsync` throw and leave the status as it was. The current state only moves once the new state is written. A
  product that relied on transitions succeeding while Redis was down now sees failed results: retry or surface them.
- ⚠ **Transition middleware runs inside the context's lock**, after the context is read, and receives the context's
  stored state as `currentState`. It no longer runs when the lock isn't acquired, the store can't be read or the
  context is `Faulted`, and it must not start a transition of the same context. Middleware that timed the lock wait
  now runs after it. A middleware that throws returns a failed result instead of throwing out of `TransitionAsync`.
- ⚠ **Results after a failed action.** A throw in an enter or after-transition action (after the state is stored)
  returns `Success = false` with `CurrentState` the stored new state and `PreviousState` the state left (it was the
  new state in both). A result whose context could not be read (lock not acquired, store unreadable) reports the
  machine's initial state as `CurrentState`. A lock action that fails returns `TransitionResult.Failed` with its
  message and exception (it was *Unknown error during transition*).
- A cancelled token throws `OperationCanceledException` up to the exit action; after it, the state is stored.

### Distributed lock
- ⚠ **An action runs once.** `RunCoordinatedActionWithRetryAsync` retries only while the lock isn't acquired: an
  action that throws runs once and its exception comes back in `Failed` (with `Exception` set), no longer retried.
  When the lock stays held it returns `LockFailed` (it was `Failed`, *All retry attempts exhausted*, in memory).
- Both `RunCoordinated*` methods let `OperationCanceledException` leave instead of returning `Failed`; the token
  reaches RedLock's `CreateLockAsync`. In Redis, an exception while taking the lock is `LockFailed` with `Exception`
  (it was `Failed` with `LockAcquired = true`).
- ⚠ **`InMemoryDistributedLock` locks per resource id and doesn't wait**: a held resource gives `LockFailed` (it was
  one semaphore for every id, and waited). Its retry delay doubles, like Redis's.
- The Redis lock connects with the password, user name and TLS from `CacheConfig`, over the same connection as values,
  opened on first use instead of in the constructor: a lock that silently never acquired on a password-protected
  server now acquires. The *Lock factory not initialized* result is gone.
- `RunCoordinatedActionWithRetryAsync` is an extension method over `RunCoordinatedActionAsync` (*Breaking changes*),
  the same loop for every lock. Its delays can follow a `TimeProvider` (`clock`, a new last parameter). The Redis lock
  no longer logs a Warning when the retries run out: the result is `LockFailed`, and each attempt still logs at Debug.
- The Redis lock answers `LockFailed` at once (`ErrorMessage` *Not connected to Redis*) while its connection is not
  connected, such as to a server that rejects the password, instead of after RedLock's synchronous timeouts (about
  40 s with the client's defaults). That includes the moments the client is reconnecting after a dropped connection.

### Redis checkpoint store
From 0.9.1, only `RedisCheckpointStore` changes; `RedisConversationMemory` stays in `Ananke.Redis`. Replace
`new RedisCheckpointStore(redis, prefix)` with `new KeyValueCheckpointStore(adapter, prefix)`
(`using Ananke.Orchestration.Checkpointing;`), where `adapter` is the `IKeyValueDataAdapter` that `AddRedis` registers.

### Key-value store
- ⚠ **A failed read is an error, not a missing key.** `IKeyValueDataAdapter` reads return null only for a missing key;
  every operation throws when the store can't answer (unreachable, timed out, a value that doesn't deserialize).
  `RedisDataAdapter` no longer logs and swallows: `GetValueAsync`, `SetValueAsync`, `RemoveAsync` and `ExistsAsync`
  throw (StackExchange.Redis exceptions, `JsonException` for a bad value). A product that called the adapter and read
  null as *Redis is down* catches the exceptions instead.
- `GetValueAsync<T>` on a key holding an empty or whitespace string throws `JsonException` (it read as missing):
  delete such values. The adapter logs its own failures at Debug, not Error; a product that alerted on its Error logs
  alerts on its own handling instead.

### MQTT
- ⚠ **`AddMqtt<TContext, TAction>` configures named options**, `MqttChannelOptions.NameFor<TContext, TAction>()`, not
  the unnamed `IOptions<ChannelConfig>`. Code that reads `IOptions<ChannelConfig>` after `AddMqtt` now gets the
  defaults (`localhost:1883`, namespace `ananke`): read
  `IOptionsMonitor<ChannelConfig>.Get(MqttChannelOptions.NameFor<TContext, TAction>())` instead, or bind the unnamed
  options itself (`services.Configure<ChannelConfig>(section)`).
- **Subscriptions at QoS 2.** The reader and the handoff channel's request and reply subscriptions use
  `ChannelConfig.QualityOfService` (default `ExactlyOnce`) instead of QoS 0. Nothing to change unless the broker
  limits QoS; set `QualityOfService = AtMostOnce` for the old subscriptions.
- `MqttHandoffChannel` no longer gives up after 10 attempts nor fails pending requests on a lost connection; they wait
  until their timeout. `ConfigureAsync` on a disposed reader or writer throws `ObjectDisposedException`; a second
  `ConfigureAsync` disposes the first client.

### Background processing
- `Start` after `DisposeAsync` throws `ObjectDisposedException` (it started a loop that ended at once); `Start` from
  several threads starts one loop; a second `DisposeAsync` waits for the loop to stop; an exception thrown by `onError`
  is reported through `onInfo` and the loop goes on (it ended the loop, and the queue then filled).

### Agents
- ⚠ **The context limit holds for the last call of a turn.** The call made at the tool-round limit, or after a tool that
  ends the turn, is measured as a tool round is (`ContextLimitMode.PreCompaction`: the raw history; `PostCompaction`:
  what is sent) and throws the context-limit error instead of going out over `WithContextLimit`.
- ⚠ **A streamed reply asked to repeat itself is returned whole.** `StreamedAgentModel` (`.Streamed()`) stops a reply
  as it arrives only once it repeats one passage over 20,000 characters (`RepeatedOutput.MinStreamedRepeatedLength`), not
  1,000. Once it ends, it is checked as an unstreamed reply is: one cut at its output limit, or that does not say why it
  stopped, throws `RepeatedOutputException` when it ends repeating over 1,000 characters; one the model ended does not.
  `new RepeatedOutput(minRepeatedLength)` watches a stream for a longer repeat.

### Analyzers
- **No more `ANANKE_ASYNC_001`.** A product referencing `Ananke.Orchestration` no longer gets it
  (`ConfigureAwait(false)`): it was this repository's own rule. A suppression of it (`.editorconfig`, `NoWarn`,
  `#pragma`) can go. The analyzer assembly in the package is `Ananke.Orchestration.Analyzers.dll`, beside
  `Ananke.Analyzers.CodeFixes.dll` (it was `Ananke.Analyzers.dll`).
- ⚠ **ANNKE002 now fires in a product.** With `TreatWarningsAsErrors`, a deprecated model id literal (such as
  `"gpt-4o"`) fails the build: replace it with the `Models.*` constant, or `#pragma warning disable ANNKE002` at the
  site.

### Models
- ⚠ **`gpt-5.4-nano` is deprecated** (OpenAI shuts it down 2027-04-01; replacement `gpt-6-luna`).
  `Models.OpenAI.Gpt54Nano` now raises ANNKE001 and the literal ANNKE002: with `TreatWarningsAsErrors` either fails
  the build.
- **New replacements for Gemini 2.5.** From 2026-12-01 Google routes `gemini-2.5-pro` to `gemini-3.8-flash` and
  `gemini-2.5-flash` to `gemini-3.5-flash-lite`; the `[Obsolete]` messages, `ReplacedBy` and the code fix now name
  those (they named `gemini-3.1-pro-preview` and `gemini-3.6-flash`).

### Knowledge
- ⚠ **Postgres keyword search ranks by BM25** (`Sparse`, and the keyword half of `Hybrid`) from lexeme counts the store
  keeps in `<table>_lexemes`, and scores only rows holding a rare query term (`RareTermShare`; a query with no rare
  term requires all its terms). Scores and order change, and a query of only common words returns fewer rows. The
  counts are over the whole table, not the rows a filter keeps: in a table shared by tenants, a term's weight comes
  from every tenant's rows. The first time a store opens an existing table (or one missing any of its triggers) it
  creates `<table>_lexemes`, a trigger function and five triggers, and fills the counts from `ts_stat`: writers wait
  while it runs, and the role must own the table and be able to create a table and a function in its schema. A
  product whose role only uses a table made for it has them made once by a role that can. Writes to one table run one
  at a time (a transaction-level advisory lock keyed by the table's oid), and `UpsertAsync` writes a batch in one
  statement, keeping the last document given for an id.
- **Postgres dense search** (`Dense`, the dense half of `Hybrid`) and `PostgresKnowledgeCatalog.DiscoverAsync` return
  the rows asked under a filter or past 40 candidates, so they can return more rows than before. Each such query runs
  in a transaction of its own with `SET LOCAL hnsw.ef_search` (at least the rows asked, at least `HnswEfSearch`, at
  most 1,000) and, on pgvector 0.8 or later, `SET LOCAL hnsw.iterative_scan` (`HnswIterativeScan = Off` is the old
  behaviour). On pgvector before 0.8 a narrow filter can still return fewer rows than asked.
- ⚠ **Lists by date.** `DatedRecordReader.ListAsync` returns the newest `limit` records, ordered and bounded by
  `effective_at` in the store, undated ones last and left out under `since`. `list_records` asks for one more than its
  maximum and says *More than N records match; the newest N* instead of counting the rest; `list_documents` likewise
  past 200. Qdrant: the store creates a datetime payload index on the order key on its first ordered list, and
  `QdrantKnowledgeCatalog` an integer index on `effective_at` the first time it browses by it
  (`CatalogBrowseOrder.EffectiveAt`), on existing collections too; `BrowseAsync` orders in the query, so it can return
  different, newer, entries than before. Postgres: ordering by date uses `pg_input_is_valid`, PostgreSQL 16 or later;
  `DatedRecordReader.ListAsync`, and so `list_records`, always orders, so on PostgreSQL 15 or earlier it now fails
  where it listed before.
- `CatalogAwareKnowledgeStore.SearchAsync` reads the catalog on every search (one `GetAsync` per source among the
  results), not only with time decay.
- A store or wrapper of your own that implements `IKnowledgeStore` applies or copies `KnowledgeFilter.AnyOf`: one that
  reads only the filter's entries ignores it, and a `DeleteAsync` whose filter holds only `AnyOf` then removes more
  than was asked.

### Usage and budgets
- ⚠ **A cost the provider reports is counted.** A call whose provider reports a cost (`TokenUsage.Cost`, such as
  OpenRouter's) and that no cost-resolving router priced is recorded with that cost as its `UsageRecord.ModelCost` and
  publishes it on `ananke.usage.cost`. A workflow budget charges such a call what the provider reported, in the
  provider's currency, instead of pricing its tokens at the budget's flat rates, and `OpenTelemetryBudgetMeter` now
  sees its cost. A call a router priced is still charged the router's cost only.

## Breaking changes

**`RedisCheckpointStore` is replaced.** `Ananke.Redis` no longer has it. Use `KeyValueCheckpointStore` (namespace
`Ananke.Orchestration.Checkpointing`) over the `IKeyValueDataAdapter` that `AddRedis` registers:
`new KeyValueCheckpointStore(adapter, prefix, logger, clock)`. `RedisConversationMemory` stays in `Ananke.Redis`; its
constructor takes `IConnectionMultiplexer` instead of `ConnectionMultiplexer`, which an existing
`ConnectionMultiplexer` still satisfies.

**`Ananke.Redis` no longer references `Ananke.Orchestration`.** A product that got `Ananke.Orchestration` (or
`Ananke.Orchestration.Knowledge`, or Polly) only through `Ananke.Redis` references it itself. A product on the lock and
values alone changes nothing, and its output loses `Ananke.Orchestration.dll`, `Ananke.Orchestration.Knowledge.dll`
and `Polly.dll`.

**The instance properties are gone.** `AbstractStateMachine` and `IActionStateMachine` lose `CurrentState`,
`OperationalStatus`, `OperationalStatusReason` and `IsInterrupted`: they were the instance's, so whichever context ran
last. Read `await machine.GetStatusAsync(context, ct)`, or use the `TransitionResult` in hand. The in-process
`StateMachine<S, T>` keeps its `CurrentState` and `IsInterrupted`.

**Tokens added.** `TransitionAsync(C, T)` and `TransitionAsync(C, T, object?)` become
`TransitionAsync(C, T, CancellationToken ct = default)` and `TransitionAsync(C, T, object?, CancellationToken ct = default)`;
likewise `NotifyAsync(C, N, CancellationToken ct = default)`, `InternalTransitionAsync` and
`IQueryableStateMachine.GetStateAsync(string, CancellationToken ct = default)`. An override adds the parameter and
passes `ct` to `InternalTransitionAsync`. Callers compile unchanged.

**Guards and actions take the context and a token.** The transition builder's `When`, `WhenAsync`, `WithAction`,
`OnEnter` and `OnExit` take `(IBaseContext context, CancellationToken ct)`: `When(() => ...)` becomes
`When((context, ct) => ...)`, and likewise for the others; the overloads without parameters are gone, and so are
the matching delegate types of `TransitionConfig.GuardCondition`, `AfterTransitionAction` and
`StateConfig.OnEnterAction`, `OnExitAction`. `AbstractStateMachine` passes the context being transitioned and the
`TransitionAsync` token; the in-process `StateMachine<S, T>` passes a context with an empty `Id`, the `FireAsync`
token to guards and `CancellationToken.None` to actions. One instance serves every context, so a guard that read a field of the machine read whichever context set it
last: read it from the context instead, cast to the machine's own context type
(`When((car, _) => ((CarContext)car).FuelLevel > 0)`). Lambdas that need neither write `(_, _) => ...`.

**Transition middleware takes a token.** `ITransitionMiddleware.InvokeAsync` and `TransitionMiddlewareBase.InvokeAsync`
take a last parameter, `CancellationToken ct`, the `TransitionAsync` token, and `next` becomes
`Func<CancellationToken, Task<TransitionResult<S>>>`. An implementation of your own adds the parameter and calls
`next(ct)` instead of `next()`; `LoggingMiddleware` and `MetricsMiddleware` do. Middleware runs inside the context's
lock, so one that waits passes `ct` to what it awaits: the lock is then freed once the token fires, not when the wait
ends.

**`IDistributedLock` has one method.** `RunCoordinatedActionWithRetryAsync` leaves the interface and becomes an
extension method on it, `DistributedLockExtensions.RunCoordinatedActionWithRetryAsync`, in the same namespace. An
implementation of your own deletes its `RunCoordinatedActionWithRetryAsync`: the extension retries through its
`RunCoordinatedActionAsync`, and a method left in place still compiles but is called only through the class, not the
interface. Callers compile unchanged.

**`IKeyValueDataAdapter`.** An implementation of your own implements the two new `SetValueAsync` overloads with a
`TimeSpan? expiry`; the two without one become default interface methods that call them with null, so it can keep or
drop them. It throws on failure rather than returning null (*Upgrading*). The `RedisDataAdapter` and
`RedisDistributedLock` constructors gain an optional third parameter, `IConnectionMultiplexer? connection`: source
compatible, but code compiled against 0.9.1 that calls them must be rebuilt.

**`IListableKnowledgeStore.ListAsync`** gains a parameter before `ct`, `KnowledgeDateOrder? order`, and so does every
implementation's (`InMemoryKnowledgeStore`, `PostgresKnowledgeStore`, `QdrantKnowledgeStore`,
`EntityScopedKnowledgeStore`). An implementation outside Ananke adds it, and a caller passing `ct` by position names it
(`ct:`). Without an order a list is as before (by id; Qdrant by point id).

**Retired OpenAI models removed.** OpenAI shut down `gpt-4.1-nano`, `o3-mini` and `o4-mini` on 2026-10-23:
