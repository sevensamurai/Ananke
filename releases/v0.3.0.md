# Ananke v0.3.0

**Theme: agents that learn by themselves.**

Two capability pillars land in this release:

- **Learning and memory** — let your agentic setup learn from experience, remember what works, and forget what doesn't.
- **Fluid communication** — make the back-and-forth between agents and the outside world more natural and responsive.

---

## What's new

### `IStateMachine<S,T>` — simplified state machine API (`Ananke.StateMachine`)

A new lightweight 2-parameter interface and factory replace the previous 4-parameter
`IActionStateMachine<C,S,T,N>` for in-process scenarios that do not require distributed
locking, context types, or notifications.

**`StateMachine.Create<S,T>`** builds a machine from a fluent transition builder:

```csharp
var machine = StateMachine.Create<Phase, Action>(Phase.Searching, b => b
    .From(Phase.Searching).On(Action.StartPaperwork).To(Phase.Paperwork)
    .From(Phase.Searching).On(Action.Interrupt).ToInterrupt(Phase.Searching)
    .From(Phase.Searching).On(Action.Resume).ToResume());

var result = await machine.FireAsync(Action.Interrupt, payload: interruptData);
```

**Interrupt stack** — `ToInterrupt(state)` pushes the current state so `ToResume` can pop
it later. Depth is capped by `StateMachineOptions.MaxInterruptDepth` (default 5).

**`TransitionResult<S>`** — rich outcome record returned from `FireAsync`:

| Property | Description |
|---|---|
| `Success` | Whether the transition fired |
| `WasInterrupt` / `WasResume` | Interrupt stack direction |
| `InterruptPayload` | Optional payload passed to `FireAsync` |
| `ResumedFromState` | The interrupt state that was exited |

**`StateMachineOptions`** — configures implicit self-transitions, lock retries, and interrupt depth.

**Lifecycle hooks** — `StateMachine<S,T>` exposes fluent registration for per-state work:

| Method | Description |
|---|---|
| `OnEnter(state, work)` | Cancellable background task started when entering a state; cancelled automatically on exit |
| `OnExit(state, work)` | Cleanup callback run after the state's CTS is cancelled but before entering the next state |
| `OnInterrupt(handler)` | Callback receiving the interrupt payload after the old state's work is cancelled |
| `OnInterrupt<TPayload>(sink)` | Typed variant accepting an `IInterruptSink<T>` (from `Ananke.Abstractions`) |

`IStateMachine<S,T>` also exposes **`IsInterrupted`** (`true` while the interrupt stack is non-empty) and **`CurrentWork`** (the `Task` for the active state's background work, observable for errors and completion).

**`IInterruptSink<T>`** (`Ananke.Abstractions`) — typed interrupt delivery contract. In-process implementations use `CancellationTokenSource` cancellation; distributed implementations can publish over a message transport (MQTT, Redis) so the interrupt reaches a remote workflow host.

**Background insights**

```csharp
machine.OnInsight<RootCauseInsight>(async (insight, state) =>
{
    if (state == Phase.Investigating)
        await session.EmitAsync("insight", insight);  // user is active — deliver inline
    else
        await insightBuffer.EnqueueAsync(insight);    // user is busy — buffer it
});

// From any background task or offline learning cycle:
await machine.SignalInsightAsync(new RootCauseInsight { Summary = "…" });
```

Multiple background processes can call `SignalInsightAsync` independently; `OnInsight<T>` chains fluently and multiple handlers may be registered for the same insight type.

### Multimodal messages — `ContentPart` hierarchy (`Ananke.Orchestration`)

`AgentMessage` now carries a `Parts` list for multimodal input. Three part types are defined:

| Type | Fields |
|---|---|
| `TextPart` | `Text` |
| `AudioPart` | `Data`, `MimeType`, `Duration?`, `Transcript?` |
| `ImagePart` | `Data?`, `Uri?`, `MimeType`, `AltText?` |

New factory helpers on `AgentMessage`:

```csharp
AgentMessage.UserAudio(audioBytes, "audio/wav")
AgentMessage.UserImage(imageBytes, "image/png", text: "What breed is this?")
AgentMessage.User([new TextPart("Describe:"), new ImagePart { Uri = uri, MimeType = "image/jpeg" }])
```

**`ModelCapability`** gains multimodal flags: `Vision`, `AudioInput`, `AudioOutput`,
`ImageGeneration`, `RealtimeStreaming`, `VideoInput`.

**`TaskRequirements.InferFrom`** automatically detects multimodal content in an `AgentRequest`
and sets the corresponding capability flags for model routing.

### `ChatSessionEvent` streaming (`Ananke.Orchestration`)

`StreamingChatWorkflow.Builder` gains a `BuildStream` method that returns an
`IAsyncEnumerable<ChatSessionEvent>` instead of relying on callback hooks:

| Event | Description |
|---|---|
| `TextDeltaEvent` | Incremental text from the model |
| `AudioDeltaEvent` | Incremental audio bytes from the model |
| `ToolCallEvent` | Model is invoking a tool |
| `ToolResultEvent` | Tool execution completed |
| `InterruptedEvent` | Generation was interrupted (carries partial text) |
| `ResumedEvent` | Generation resumed after an interrupt |
| `CompletedEvent` | Conversation turn completed |
| `ErrorEvent` | Error during generation |

**`AgentMessageExtensions.PatchOrphanedToolCalls`** repairs conversation history after an
interrupt that occurred mid–tool-call. Without this patch, providers reject the follow-up
request because every `tool_calls` entry must have a matching `tool` result message.

### Empirical memory — third memory layer (`Ananke.Orchestration`, `Ananke.Qdrant`)

A new `IEmpiricalMemory` interface adds a third memory tier alongside semantic knowledge
stores and episodic conversation memory. Entries are typed by `EmpiricalKind`:

| Kind | Meaning |
|---|---|
| `Pattern` | Observational: "when X happens, Y follows" |
| `Skill` | Procedural: "how to investigate X" |
| `Heuristic` | Rule of thumb: "prefer X over Y in situation Z" |

**Core operations:**

```csharp
await memory.CommitAsync(entry);                        // store or reinforce
var matches = await memory.RecallAsync("situation…");   // ranked recall
await memory.ReinforceAsync(id, reinforcement);         // confirm a pattern
await memory.ContradictAsync(id, reason);               // weaken without deleting
```

**`EmpiricalMemoryTools.Create(memory)`** — factory that produces a `ToolKit` with three
agent-callable tools: `recall_empirical`, `commit_insight`, and `reinforce_empirical`.

**Affective learning signals** — `EmpiricalEntry` gains five optional fields that enable information-theoretically grounded reinforcement:

| Field | Type | Description |
|---|---|---|
| `Strength` | `float` | Belief strength — decays over time; drives garbage collection |
| `Variance` | `float` | EMA of squared prediction errors; derives `Confidence` via `1 / (1 + Variance)` |
| `LastPredictionError` | `float` | Most recent `\|predicted − actual\|` — diagnostics and reinforcement cooldown |
| `Valence` | `float` | Surprise direction: `actual − predicted` (−1.0 worse than expected → +1.0 better than expected) — influences recall priority, not truth |
| `Intensity` | `float` | Surprise magnitude: `\|predicted − actual\|` (0.0 expected → 1.0 maximally unexpected) — influences recall priority, not truth |

When `Reinforcement.Reward` is supplied, reinforcement becomes prediction-error-modulated: expected outcomes produce a small strength increase; surprising ones update `Variance` more aggressively, lowering derived confidence. Without `Reward`, the previous flat behaviour is preserved for backward compatibility.

Recall scoring applies a priority boost proportional to `Intensity × |Valence|`, surfacing high-stakes discoveries above routine observations without altering stored confidence values.

**`SemanticDescription`** — structured content descriptor on `EmpiricalEntry` that replaces a plain string with a human-readable `Summary` and a dictionary of weighted `SemanticTags` (e.g. `"cause:gc-pause" → 0.9`). Tags enable causal-aware deduplication, dimension-projected recall, and gap-aware exploration beyond embedding-only similarity. `ToEmbeddingText()` combines the summary with tag keys for richer vector coverage.

**`IPredictionSource`** — optional interface that decouples the prediction step from confidence. When provided, it is called during `ReinforceAsync` to form an independent prediction before computing prediction error; confidence then derives purely from variance rather than being used as its own predictor. `TagOverlapPredictionSource` ships as a built-in tag-overlap implementation. Omitting `IPredictionSource` preserves the original confidence-as-prediction fallback.

**`AffectOptions`** — encapsulates all learning parameters with documented defaults: learning rate, EMA smoothing factor, base decay rate, variance-amplified decay multiplier, deletion threshold, priority boost cap, reinforcement cooldown, contradiction strength/valence/intensity penalties, and evidence cap. Pass an `AffectOptions` instance to `InMemoryEmpiricalMemory` or `QdrantEmpiricalMemory` to opt into the affective model; omitting it preserves the previous behaviour exactly.

**Built-in implementations:**

| Implementation | Package | Use case |
|---|---|---|
| `InMemoryEmpiricalMemory` | `Ananke.Orchestration` | Tests / single-process |
| `QdrantEmpiricalMemory` | `Ananke.Qdrant` | Distributed, persistent |

### Offline learning — `IOfflineLearner` (`Ananke.Orchestration`)

A background learning service closes the loop between what the agent observes during conversations and what it permanently retains. While `IEmpiricalMemory` captures individual reinforcements inline, the offline learner runs independently — on a timer, between sessions, or between game rounds — to consolidate, prune, and actively explore the accumulated knowledge base.

**`IOfflineLearner`** exposes two entry points:

```csharp
OfflineLearningResult result = await learner.LearnAsync(ct);  // full cycle: decay + curiosity walk + consolidation
int removed                  = await learner.DecayAsync(ct);   // decay sweep only
```

**`OfflineLearningResult`** summarises a completed cycle:

| Property | Description |
|---|---|
| `Decayed` | Entries pruned below the strength threshold |
| `Explored` | Entries examined during the curiosity walk |
| `Reinforced` | Entries whose prediction was confirmed |
| `Contradicted` | Entries whose prediction failed |
| `Consolidated` | Entries promoted to `IKnowledgeStore` during consolidation |
| `Discoveries` | Natural-language summaries ready for delivery via `SignalInsightAsync` |

**The learning loop** runs three stages per cycle:

1. **Decay** — every entry loses strength per cycle; entries with high `Variance` lose additional strength so unstable beliefs fade faster. Entries below the deletion threshold are soft-deleted.
2. **Curiosity walk** — entries with high recent prediction error are preferred for re-evaluation alongside a random fraction (ε-greedy). For each, the learner searches the knowledge base and optionally runs imagined scenarios via `ISimulationSource`, computes an intrinsic reward from a weighted matrix (confirmation, surprise, noise, contradiction), and autonomously calls `ReinforceAsync` or `ContradictAsync`.
3. **Discovery delivery** — when a curiosity step yields an intrinsic reward above the discovery threshold, the learner surfaces it as a natural-language insight via `SignalInsightAsync` (if a session is active) or routes it to an offline channel such as email or a notification queue.
4. **Consolidation** — mature entries (high strength, low variance, sufficient observations) are promoted to `IKnowledgeStore` via `IConsolidationSummarizer` and marked with `ConsolidatedInto` so they are excluded from future exploration.

**`ISimulationSource`** — optional interface the application provides to let the learner generate imagined evidence (self-play, Monte Carlo rollouts). Simulation evidence is always down-weighted relative to real observations (`SimulationEvidenceWeight` defaults to `0.3`).

**`IConsolidationSummarizer`** — generates a `KnowledgeDocument` from a mature `EmpiricalEntry` for upsert into `IKnowledgeStore`. `TemplateConsolidationSummarizer` ships as an LLM-free string-interpolation implementation suitable for tests and well-structured domains.

**`OfflineLearnerOptions`** collects all tuning knobs: exploration batch size, curiosity threshold, ε-greedy fraction, discovery threshold, simulation budget, intrinsic reward matrix weights (confirmation, noise, contradiction), consolidation eligibility thresholds, and the nested `AffectOptions` shared with the reinforcement model.

**`InMemoryOfflineLearner`** ships in `Ananke.Orchestration` for testing and single-process use.

### `KnowledgeBase` — multi-section knowledge grouping (`Ananke.Orchestration`)

Groups one or more named `KnowledgeSection`s with a shared `IKnowledgeCatalog` into a single
dependency, eliminating the need to thread multiple store references through every constructor.

```csharp
var kb = new KnowledgeBase(
    [new("pets", petStore), new("policies", policyStore)],
    catalog);

// Fan-out search across all sections (merged by score)
var results = await kb.SearchAsync("family-friendly dogs");
foreach (var r in results)
    Console.WriteLine($"[{r.Section}] {r.Chunk.Text}");

// Target a specific section
var petResults = await kb["pets"].Store.SearchAsync("golden retriever");
```

### `Ananke.AspNetCore` — new package

A new `Ananke.AspNetCore` package provides ASP.NET Core integration for state-machine–driven
SSE chat applications.

**`ChatSession<TState,TAction>`** — base class that bundles a `StateMachine<S,T>`, an
`IStreamingAgentModel`, a conversation history list, and per-request SSE binding.
Subclass to add domain-specific state.

**`InMemorySessionStore<T>`** — thread-safe `ConcurrentDictionary`-backed session store.
Supports `GetOrCreate`, `TryGet`, `Remove`, and `RemoveAndGet`.

**`SseResponseExtensions.WriteSseAsync`** — writes a named `event: <name>\ndata: <json>\n\n`
SSE frame to an `HttpResponse`.

**`ChatSessionEventSseExtensions.WriteSseAsync`** — maps a `ChatSessionEvent` stream to SSE
events (`delta`, `audio_delta`, `tool_call`, `tool_result`, `interrupted`, `resumed`, `error`).

**`StateMachineSseExtensions.RunSseLoopAsync`** — drives the state machine SSE loop across
request boundaries, surviving interrupt-induced cancellation and the brief race window
during state transitions.

## Breaking changes

### `Ananke.Orchestration` — `ChatSessionHandle` and `InterruptableSession` removed

`ChatSessionHandle` and `InterruptableSession` have been removed. Interrupt handling is
now a first-class feature of `IStateMachine<S,T>` via `ToInterrupt` / `ToResume` transitions.
Replace session management with `ChatSession<S,T>` from `Ananke.AspNetCore`.

### `Ananke` — `InterruptableBridge` and `WorkflowTriggerAction` removed

`InterruptableBridge` and `WorkflowTriggerAction` have been removed from `Ananke.Bridge`.
The interrupt pattern they implemented is superseded by the state machine interrupt stack.

### `StreamingChatWorkflow` — callback-based API replaced by `BuildStream`

The previous callback hooks (`OnTextDelta`, `OnToolCall`, etc. resolved via `RunAsync`) are
still present but the preferred pattern is now `BuildStream` / `IAsyncEnumerable<ChatSessionEvent>`,
which integrates directly with `ChatSessionEventSseExtensions`.

## Ecosystem

Ananke is a .NET framework for foundational intelligence where reasoning and self-improvement
evolve rather than simple orchestration. It stays **deliberately .NET-native** — wrapping it
as a Python library purely out of fear of missing adoption would compromise both ecosystems.
Cross-language interoperability is addressed cleanly via the **A2A** (Agent-to-Agent) protocol,
letting heterogeneous application blocks communicate without coupling to a single runtime.
