# Ananke v0.8.0

**Theme: Pluggable Organic Growth + Federation + Smart Tool Router — `OrganicHost` + `.JoinHost()` replace ~40 lines of manual wiring; `Ananke.Federation` extends organic division across platform boundaries; `nnke-platform` CLI brings federation lifecycle management to the terminal; the Smart Tool Router brings declarative, multi-stage tool selection with a biology-inspired cascade.**

Workflows join an `OrganicHost` via `.JoinHost(host, toolKit)` and get automatic complexity monitoring, policy evaluation, and gate-driven division approval — all at the execution boundary, without touching the workflow's runner, checkpointing, or tracing. When division targets a remote platform, `FederatedDivisionPolicy` selects the right deployment profile and `PlatformDivisionApprovalGate` enforces human oversight before any cross-boundary deployment.

The Smart Tool Router replaces the single-stage `SemanticToolGate` (introduced mid-cycle, never released) with a composable, pluggable pipeline. Each stage narrows or re-ranks the candidate tool window before it reaches the frontier model. Routing is declared in `.ananke.yml` — no code changes needed for common configurations.

## Manifest schema addition — `router:` block

Jobs may now declare a `router:` block under `jobs:`:

```yaml
jobs:
  plan:
    type: agent
    model: fast
    tools:
      - search
      - list_tools
    router:
      - kind: pinned
        tools: [list_tools]
      - kind: health_filter
      - kind: semantic_recall
        top_k: 8
      - kind: affinity_rerank
      - kind: llm
        model: fast
        max_selected: 3
```

Supported kinds: `pinned`, `health_filter`, `semantic_recall`, `affinity_rerank`, `heuristic_tags`, `llm`.
Validation errors use diagnostic codes `ANANKE_ROUTER_001` (unknown kind) and `ANANKE_ROUTER_002` (missing model reference in `llm` stage).

## New tools — `nnke-platform` CLI

```
nnke-platform [--json] <command>
```

| Command | Purpose |
|---|---|
| `validate <file>` | Run `DeployabilityValidator` against a `.ananke.yml` manifest |
| `capabilities` | List platform capabilities loaded from `platform-capabilities.json` |
| `profiles <file>` | Show deployment profiles defined in a manifest |
| `deploy <file>` | Deploy a workflow to its configured target platform |
| `status [--deployment-id]` | Show status of active deployments |
| `teardown --deployment-id` | Remove a remote deployment |
| `trends [--deployment-id]` | Show `RemoteMetricsTracker` trends (tokens/exec, tool-calls/exec) for remote cells |
| `analyze <file> [--deployment-id]` | Correlate manifest structure with runtime trends — surfaces "add tool → tension rises" patterns and recommends division or platform placement changes |

All commands support `--json` for machine-readable output.
