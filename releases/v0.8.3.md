# Ananke v0.8.3

**Theme: `nnke` developer experience — new scaffold targets, MCP server mode, and a restructured command surface.**

No breaking changes to library APIs. This release focuses entirely on the `nnke` developer tool:
a rewritten command hierarchy, two new first-class scaffold targets, a new `nnke mcp-server` mode
that exposes all nnke commands as MCP tools, and a cleaner template engine.

## What's new

### `nnke new` — restructured scaffold commands

The `nnke new` surface has been split into four focused subcommands so the intent of each scaffold
is immediately clear:

| Command | What it creates |
|---|---|
| `nnke new quickstart <name>` | Minimal console workflow aligned with Guide 01; runs immediately with `SimulatedModel` — no API key required |
| `nnke new workflow <name> --pattern <key>` | Full workflow project (`.ananke.yml`, `Program.cs`, `PipelineState.cs`, `secrets.json`) for any of the eleven supported patterns |
| `nnke new chatbox <name>` | ASP.NET Minimal API with `POST /chat` and `POST /chat/stream` (SSE) backed by `StreamingChatWorkflow`; runs without an API key |
| `nnke new pattern <name> --pattern <key>` | Discoverable alias for `new workflow` — surfaces the pattern catalog inline; accepts `--list` to print the full catalog and exit |

### `nnke new chatbox` — streaming API scaffold

The new `chatbox` target generates a production-ready conversational agent server in one command:

```
nnke new chatbox MyChatbot --provider anthropic
```

- `POST /chat` — full JSON response
- `POST /chat/stream` — Server-Sent Events with token-by-token streaming
- `SimulatedStreamingModel` wired by default; swap to a real provider by editing one constant

### `nnke new quickstart` — zero-friction onboarding

`nnke new quickstart <name>` replaces the old default scaffold. The generated project:

- Compiles and runs without any configuration changes
- Uses `SimulatedModel` so no API key or network is required
- Generates four files: `<name>.csproj`, `Program.cs`, `QuickstartState.cs`, `README.md`

### `nnke mcp-server` — expose nnke as an MCP server

`nnke mcp-server` starts a local MCP server that exposes all nnke commands as callable tools.
AI assistants and IDE integrations can scaffold projects, search documentation, inspect running
meshes, and validate manifests without leaving their chat surface:

| MCP tool | Maps to |
|---|---|
| `ananke_scaffold_quickstart` | `nnke new quickstart` |
| `ananke_scaffold_chatbox` | `nnke new chatbox` |
| `ananke_scaffold` | `nnke new workflow --pattern` |
| `ananke_docs_search` / `ananke_docs_read` / `ananke_docs_list` | `nnke docs` |
| `ananke_explain` / `ananke_explain_list` | `nnke explain` |
| `ananke_patterns_list` / `ananke_patterns_describe` | `nnke patterns` |
| `ananke_inspect` | `nnke inspect` |
| `ananke_validate` | `nnke validate` |
| `ananke_mesh_status` / `ananke_cell_trace` / `ananke_memory_inspect` / `ananke_lineage` | mesh commands |

All MCP tools return structured JSON matching the `--json` flag of the corresponding CLI command.

### `nnke new pattern --list`

`nnke new pattern --list` prints the full pattern catalog and exits, so users can discover patterns
without switching to a separate `nnke patterns` invocation.

### Template engine cleanup

- `TemplateEngine` consolidated into a single rendering path; removes the previous dual
  `.cs-template` / `.cs.template` lookup confusion.
- `ProjectTemplate` unified across `quickstart`, `chatbox`, `workflow` (code-only), and
  `workflow` (manifest-driven) project types — one renderer, different `ProjectType` variants.
- `QuickstartTemplate`, `ChatboxTemplate`, and `ReadmeTemplate` are now distinct classes with
  dedicated `RenderProgram`, `RenderState`, and `RenderReadme` methods for clear separation.
- `secrets.json` template added for chatbox and workflow scaffolds (`SecretsTemplate.Render`).
- All template resource files use consistent `.{ext}.template` naming under `Templates/Resources/`.

### `nnke` command surface additions

Two commands were already wired in 0.8.2 but are now properly registered and discoverable:

- `nnke schema` — emit JSON Schema for `.ananke.yml` manifests; supports `--output` to write to a file.
- `nnke kernel` — start a Jupyter-style interactive kernel session for iterative workflow exploration.

### `check-nnke-deps.ps1` script

A new `scripts/check-nnke-deps.ps1` helper validates that the local `nnke` tool binary references
the same `Ananke.*` package versions as the solution, catching version drift before publishing.

## Breaking changes

None. Library API surface is unchanged.
