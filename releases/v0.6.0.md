# Ananke v0.6.0

**Theme: public documentation site, messaging platform channels & external knowledge ingestion.**

Three capability pillars land in this release:

- **GitHub Pages documentation site** — a full static documentation site deployed to [sevensamurai.github.io/Ananke](https://sevensamurai.github.io/Ananke), covering 18 guides, 4 reference pages, 3 about pages, an FAQ, and a progressive learning path — all with syntax-highlighted C# examples and dark/light mode.
- **Messaging platform channels** — `Ananke.Platforms`, `Ananke.Platforms.Slack`, and `Ananke.Platforms.Discord` provide a unified adapter model for bridging chat platforms to Ananke agent workflows, with session management, streaming post-then-edit, and conversation memory wired in out of the box.
- **External knowledge ingestion** — `IExternalKnowledgeSource<TEvent>` and `ExternalKnowledgeSyncer<TEvent>` in `Ananke.Learning.Ingestion` give products a standard pattern for pre-materializing domain-specific external data (GitHub releases, supplier shipments, firmware updates, etc.) into the agent knowledge store.

### `Ananke.Platforms` — messaging platform adapters (new)

Three new packages provide a layered adapter model for connecting messaging platforms to Ananke streaming workflows.

**`Ananke.Platforms`** defines the shared contracts:

| Type | Purpose |
|---|---|
| `IMessagePlatformAdapter` | Platform connection lifecycle — `StartAsync`, `StopAsync`, `IsConnected` |
| `IPlatformResponseSink` | Send responses: `SendMessageAsync`, `UpdateMessageAsync`, `SendTypingAsync`, `AddReactionAsync` |
| `IPlatformMessageHandler` | Business logic hook: route incoming messages to workflows |
| `PlatformMessage` | Normalized incoming message: `ChannelId`, `ThreadId`, `UserId`, `Message` |
| `StreamingMessageBridge` | Bridges `StreamingChatWorkflow.OnTextDelta` to the post-then-edit pattern with configurable debounce |
| `ConversationalMessageHandler` | Abstract base: session-aware, memory-integrated handler that eliminates boilerplate |
| `SessionKeyBuilder` | Derives collision-free session keys from platform message properties |

**`ConversationalMessageHandler`** is the recommended starting point. It automatically:

1. Sends a typing indicator
2. Derives a session key from channel/thread identifiers
3. Loads conversation history from `IConversationMemory`
4. Runs `StreamingChatWorkflow` with `StreamingMessageBridge`
5. Persists new messages to memory

```csharp
public sealed class MyBotHandler(IAgentModel model, IConversationMemory memory)
    : ConversationalMessageHandler(model, memory)
{
    protected override string? SystemPrompt => "You are a helpful assistant.";

    protected override void ConfigureWorkflow(StreamingChatWorkflowBuilder b, PlatformMessage msg)
        => b.WithTools(new MyToolKit());
}
```

**`Ananke.Platforms.Slack`** — Slack adapter via Socket Mode (no public URL required):

```csharp
var adapter = new SlackAdapter(slackClient, new SlackAdapterOptions
{
    BotToken     = "xoxb-…",
    AppToken     = "xapp-…",
    MessageHandler = serviceProvider.GetRequiredService<MyBotHandler>()
});
await adapter.StartAsync(cancellationToken);
```

**`Ananke.Platforms.Discord`** — Discord adapter with slash command support:

```csharp
var adapter = new DiscordAdapter(discordClient, new DiscordAdapterOptions
{
    BotToken       = "Bot …",
    MessageHandler = serviceProvider.GetRequiredService<MyBotHandler>()
});
await adapter.StartAsync(cancellationToken);
```

Both adapters stream responses using the post-then-edit pattern: the first chunk creates a message; subsequent chunks silently update it until the stream ends.

### External knowledge ingestion — `Ananke.Learning.Ingestion` (new)

`IExternalKnowledgeSource<TEvent>` and `ExternalKnowledgeSyncer<TEvent>` establish a standard pattern for products to pre-materialize external data into the agent knowledge store.

**`IExternalKnowledgeSource<TEvent>`** — implement once per domain:

```csharp
public sealed class GitHubReleaseSource(GitHubClient github)
    : IExternalKnowledgeSource<ReleaseEvent>
{
    public async Task<ResolvedKnowledgeBatch> ResolveAsync(
        ReleaseEvent @event, CancellationToken ct = default)
    {
        // Fetch commits, PRs, cards from GitHub API
        // Return as KnowledgeDocument collection
        ...
    }
}
```

**`ExternalKnowledgeSyncer<TEvent>`** — call from a webhook handler or scheduled worker:

```csharp
var syncer = new ExternalKnowledgeSyncer<ReleaseEvent>(
    source: new GitHubReleaseSource(github),
    knowledgeStore: knowledgeStore,
    logger: logger);

SyncResult result = await syncer.SyncAsync(releaseEvent, ct);
// result.Written — documents upserted
// result.Failed  — documents that errored (batch continues on failure)
```

The syncer ensures idempotent upsert (via `IKnowledgeStore.UpsertAsync`), error isolation per document, and structured result reporting for observability.

**Demo:** [`LogEventsDemo`](../src/demos/LogEventsDemo/)

### `QdrantEmpiricalMemory` — Qdrant-backed empirical memory

`Ananke.Qdrant` now exposes `QdrantEmpiricalMemory`, an `IEmpiricalMemory` implementation backed by a Qdrant vector collection. It mirrors the contract of `InMemoryEmpiricalMemory` and can be used as a drop-in persistent replacement.
