# Ananke v0.8.9

**Theme: cost budgets, fork-branch guarantees, and clearing the code-quality backlog**

The quality release. Two new capabilities — **spend budgets with usage accounting**, and
**fork branches that report what happened to them** — land alongside roughly two dozen fixes from
the code-quality review. No new provider adapters, no new platform surface.

This is a large changeset (68 commits, 142 files) and the notes below stay at summary level. The
per-item detail lives in the backlog and the two ADRs it points at.

---

## What's new

### Spend budgets and usage accounting

A workflow can now be given a cost ceiling and will stop when it reaches it.

- `Workflow<TState>.WithBudget(maxCost)` for a flat run budget, `WithBudgetPerMillion(input, output)`
  to declare rates the way providers publish them, or `WithBudget(BudgetConfig)` for full control.
- **Warn or stop.** `WarnAtCost` emits a `BudgetWarning` lifecycle event and lets the run continue;
  crossing `MaxCost` emits `BudgetExceeded` and stops. Inside a fork, an exhausted budget stops the
  branch and reports it as `BranchOutcomeKind.Stopped` rather than a fault.
- **Periods.** `PeriodCostLimit` / `WarnAtPeriodCost` track spend across runs on a calendar-month
  window with a configurable anchor day, keyed per `BudgetId`.
- **Usage recording is a seam.** `IUsageRecorder` with an in-memory default and a file-backed
  `FileUsageRecorder`; `UsageSnapshot` separates costed spend from `UncostedUsage`, so a run that
  mixes priced and unpriced models reports both honestly instead of understating the total.

Rates are figures you declare — Ananke ships no rate table and does not price models for you. A
richer model (plan, tier, zone) is left for later, behind the existing `IModelCostResolver` seam.

### Fork branches now report their outcomes

Previously a fork discarded what happened inside each branch. Now every branch produces a
`BranchOutcome` — `Succeeded`, `Faulted`, `Cancelled`, or `Stopped` — surfaced on the execution, on
the result, and via a new `BranchFaulted` lifecycle event. `Join` gains an outcome-aware overload
taking a `JoinContext<TState>` so a merge can see which branches actually succeeded.

Two previously-silent failure modes now fail loudly instead (see Breaking changes): an interrupt
configured inside a fork, and a nested fork. Both need branch-local checkpointing that does not
exist yet, and both used to resolve to something quietly wrong.

Cancellation tokens now reach routing inside fork branches, loops inside branches resolve
correctly, and lifecycle events carry the branch they belong to.

Authority for all of this: **ADR-arch-025** (branch failure semantics) and **ADR-arch-028** (fork
guarantees and budget).

### Code-quality backlog

Roughly two dozen review items, the substantial ones being:

- **A sandbox escape in `TextEditorExecutor`** — relative `../` paths escaped the sandbox root.
- **`AgentJob`/`TextAgentJob` deduplicated.** 17 near-identical methods with no shared base had
  already produced three bugs where a fix landed on one type and not the other. Execution logic now
  lives once in an internal `AgentJobEngine`; public behaviour is unchanged.
- **`CancellationToken` threaded through** `IDistributedLock`, `IKeyValueDataAdapter`, `IWorkflowHost`
  stop/pause/resume, channel `ClearAsync`, and state-machine persistence — all previously had network
  calls or retry loops with no way to abort.
- Qdrant `EmpiricalEntry.Latency` no longer truncates to whole minutes; `GeminiAgentModel.Create`
  gains an endpoint override; handoff channels are bounded; plus several corrected doc and ADR claims.
- **`CancellationToken` reaches the SSE and state-machine paths that never had it.** The SSE event
  loop, `ChatSession.StreamAsync` and the state-machine SSE loop now observe
  `HttpContext.RequestAborted`, so a disconnected client stops the work instead of letting it run on.
  `IStateMachine.FireAsync` and `SignalInsightAsync` accept one too — both are serialized behind a
  single gate, and a caller queued behind an in-flight transition previously had no way to give up.
  See Breaking changes.
- **Cross-provider model mapping filled in.** The OpenAI and Gemini mappers had no entries for
  Anthropic's current models, so an Anthropic-sourced manifest simply failed to map. Anthropic's own
  mapper now also reports capabilities for its current flagships, which previously returned `null`.
- **127 `catch (Exception)` sites triaged.** 117 already converted the failure into something
  observable; the 5 that discarded it with no trace now record why the swallow is intentional.

### `nnke-platform` CLI correctness

v0.8.8 fixed exit codes for `nnke`. This release fixes the same class of problem in
`nnke-platform`, which had been missed:

- **Every command now returns a meaningful exit code.** `validate` reported `BLOCKED — fix errors
  before deploying` and exited `0`, so a CI gate on it always passed. See Breaking changes.
- **`adapters list`/`doctor` can now see installed adapters.** Both read diagnostics that only the
  platform host populates, which neither command constructed — so both reported "no adapters
  installed" whatever was on disk.
- **`compare --across azure-ai,claude` now splits on commas** instead of treating the documented
  comma form as one platform literally named `azure-ai,claude`.

All three were behaviours the docs already described correctly. Locked in by 25 new tests that
invoke commands through the real pipeline and assert exit codes — the gap that let all three ship.

### Streaming responses now carry structured content

`AgentResponse.Parts` had no stated contract, so each adapter did something different — and
Anthropic populated it on `GenerateAsync` but not on `GenerateStreamAsync`, silently dropping
content for anyone who switched to streaming. [ADR-arch-029](https://github.com/sevensamurai/Ananke)
settles it: **`Parts` is required whenever a response carries anything that is not plain text**
(reasoning, image, audio, document), and may be `null` for a purely textual reply. The same rule
binds both the unary and streaming paths.

Anthropic's streaming path now emits `ReasoningPart` — including its signature, which arrives as a
separate delta and is what makes multi-turn reasoning continuation possible. `AgentStreamChunk` is
unchanged: reasoning is only well-formed once its block closes, so streaming it incrementally would
have added public API for very little. See Breaking changes.

### `DocumentPart` support across the three provider adapters

Google, Anthropic and OpenAI can now send document content — support is asymmetric because the
SDKs are: Google accepts bytes or a URI (same channel as images), Anthropic accepts PDF or
plain-text bytes or a PDF URL, OpenAI accepts bytes only (no URI overload exists). Anything outside
those shapes still throws `NotSupportedException` with a message naming the actual reason (wrong
MIME type, URI-only with no upload path) instead of the old generic "not supported" text. See
Breaking changes.

Anthropic's captured reasoning `Signature` (from `ReasoningPart`) can now be echoed back on the
request side via `ThinkingBlockParam`/`RedactedThinkingBlockParam`, unblocking multi-turn
continuation for providers that require it. OpenAI and Google still throw on `ReasoningPart` — neither
emits reasoning content today, so there is nothing to echo.

### Test coverage and analyzers

- New test projects for **`nnke`**, **`Ananke.Qdrant`**, and **`Ananke.Orchestration.Knowledge`**,
  all of which had none, plus `nnke-platform`'s test projects registered in the solution (they were
  building but never running).
- **`ANANKE_TIME_001` (ambient clock) retired.** It flagged every `DateTimeOffset.UtcNow` including
  the legitimate ones, and `TimeProvider` guidance in `CLAUDE.md` and review already covered it
  better than a blanket rule. `ANANKE_ASYNC_001` (`ConfigureAwait`) stays. See Breaking changes.
- **`ANANKE_ASYNC_001` migration finished.** All 33 remaining files (460 bare awaits across 13
  projects) now call `ConfigureAwait(false)`. The legacy-suppression block in `src/.editorconfig`
  drops from 57 entries to 18 — the 8 whole-project wildcards (`demos/**`, `nnke*/**`) and 10
  individual test-file entries, both permanent by design.
- **Every archived ADR now records a real status.** 24 documents under `internals/foundation/` still
  read `Status: Proposed` long after the work shipped; each now names its evidence and what was not
  re-verified. Two genuine gaps surfaced that stale labels had hidden.
- Documentation drift swept out of the public docs: a wrong package name in `llms-full.txt`, a
  non-existent `nnke mcp` command in the root README, several commands documented but removed in an
  earlier release, and two broken links.

## Carried forward

Not everything in the backlog landed. Deliberately open, each needing its own iteration:

- **In-fork checkpointing** (ADR-arch-028 D5) — the one fork guarantee not closed. Recovery replays
  fork work, and it is why in-fork interrupts throw rather than pause. `Q2 part 2 done` does **not**
  mean forks are finished.
- A real cost model, `AgentDivisionPolicy` (ADR-arch-026), and the `Ananke.Abstractions` contract
  freeze all remain scheduled past this release.

## Breaking changes

### `nnke-platform` commands report failure via exit code

**Who is affected:** scripts and CI calling any `nnke-platform` command that checked only stdout.

**What changes:** commands now exit `0` on success, `1` on a usage or I/O error (missing file,
unknown platform or profile), and `2` when the command ran but the answer is negative (manifest not
deployable, adapter unhealthy). Previously almost everything exited `0`.

**Migration:** none if you already check exit codes. A gate on `nnke-platform validate` that used to
pass unconditionally will now correctly fail on a blocked manifest — expect that to surface real
problems the first time it runs.

### Interrupts and nested forks inside a fork branch now throw

**Who is affected:** any workflow configuring an interrupt on a job inside a fork, or nesting a fork
inside a forked branch.

**What changes:** both throw `NotSupportedException` with a message naming the job. Previously the
interrupt was silently ignored — turning "pause for a human" into "skip the gated work" — and a
nested fork truncated the branch without a word.

**Migration:** move the interrupt outside the fork, or flatten the inner fork / move it into a
`SubFlow`, which runs its own workflow and supports forks normally.

### `CancellationToken` parameters added to several interfaces

**Who is affected:** external implementers of `IDistributedLock`, `IKeyValueDataAdapter`,
`IWorkflowHost`, or the channel reader/writer interfaces. Callers are unaffected — the parameters
are optional.

**Migration:** add the `CancellationToken ct = default` parameter to your implementing members.

### Adapters that threw on `DocumentPart` now accept it

**Who is affected:** callers catching `NotSupportedException` around a `DocumentPart` sent to the
Google, Anthropic or OpenAI adapters — that shape is what the previous release note referred to as
"partial" support.

**What changes:** Google now accepts document bytes or a URI; Anthropic accepts PDF or plain-text
bytes, or a PDF URL; OpenAI accepts document bytes (no URI overload exists in its SDK). A
`DocumentPart` outside those shapes still throws, but the message now names the specific reason
(unsupported MIME type, or a URI-only document where bytes are required) instead of a generic
"not supported by this adapter" message.

**Migration:** none required — this only removes exceptions for cases that previously always
failed. Code that depended on the throw (e.g. to detect "documents unsupported") needs updating.

### `claude-opus-4-1` removed — Anthropic retired it on 2026-08-05

**Who is affected:** anyone referencing `Models.Anthropic.Opus41` or the literal `claude-opus-4-1`.

**What changes:** the constant, its `model-lifecycle.json` entry and both catalog registrations are
gone. Retired models are deleted outright rather than kept with a `Retired` status, because a
constant for a model the provider no longer serves only lets new code reference an always-failing id.

**Migration:** use `Models.Anthropic.Opus5`. Note this is Ananke's replacement, not Anthropic's
literal one (`claude-opus-4-8`) — a recommended replacement must itself be current, and 4.8 is Legacy.

### Anthropic streaming now populates `AgentResponse.Parts`

**Who is affected:** callers of `GenerateStreamAsync` against Anthropic that treated
`CompletedResponse.Parts is null` as "no structured content".

**What changes:** when the response carries reasoning, `Parts` is now populated (per ADR-arch-029 D1),
matching what the unary path already did. Purely textual responses still leave it `null`.

**Migration:** treat `Parts is null` as "text-only", not "no content" — `Text` is still derived from
any `TextPart` entries, so code reading `Text` is unaffected.

### `IStateMachine<S,T>.FireAsync` gains a `CancellationToken`

**Who is affected:** external implementers of `IStateMachine<S,T>`. Callers are unaffected — the
parameter is optional.

**Migration:** add `CancellationToken ct = default` to your `FireAsync`. `StateMachine<S,T>` is the
only in-tree implementer.

### `ANANKE_TIME_001` no longer exists

**Who is affected:** anyone with `#pragma warning disable ANANKE_TIME_001` blocks, or relying on the
diagnostic to catch ambient-clock use.

**Migration:** the pragmas are now inert and can be deleted at leisure. `TimeProvider` remains the
convention for injectable time; it is simply no longer enforced by an analyzer.
