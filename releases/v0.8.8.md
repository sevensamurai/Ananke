# Ananke v0.8.8

**Theme: reasoning content correctness, safer completion-logging default, and Anthropic-adapter symmetry**

Phase 1 of an upstream sequencing effort, plus three carried-over architecture cleanup items. No
new features — two correctness fixes on reasoning models and completion logging, one adapter
parity fix, and test/dependency hardening. Also folds in five fixes from the code-quality review
(see "Code-quality fixes" below) — landed before merge rather than waiting for the next release.

---

## What's new

### Reasoning content no longer leaks into `.Text`

- Anthropic `thinking`/`redacted_thinking` blocks now map to a new `ReasoningPart` content part
  (carrying the reasoning text, an optional opaque `Signature` for providers that require it
  echoed back on a later turn, and an `IsRedacted` flag) instead of being folded into the same
  parts list as response text.
- `AgentResponse.Text` already excluded non-`TextPart` content — the fix was upstream of that,
  in what `AnthropicAgentModel.MapMessage` put into `Parts`. See Breaking changes.
- New `DocumentPart` content part (raw bytes or URI, required MIME type, optional name),
  following `ImagePart`'s shape, added in the same pass.
- Scope: the Anthropic *streaming* path (`GenerateStreamAsync`) still drops thinking deltas
  entirely rather than emitting them — accumulating a streamed signature belongs with later
  streaming-primitive work, not this release. OpenAI and Google adapters are untouched; neither
  emits reasoning content today.

### `StoreCompletions` now defaults to `false`

- Completions no longer land in the provider's platform-side logs unless explicitly opted in.
  Flipped at all ten sites that determine the effective default, including five `?? true` fallback
  sites (`AgentJob`, `TextAgentJob`) that apply whenever there is no ambient workflow trace
  context — i.e. every agent job run outside a workflow, the common standalone path. See Breaking
  changes.

### Anthropic adapter: base-URL override

- `AnthropicAgentModel.Create(apiKey, model, endpoint: Uri?)` — matches
  `OpenAIChatAgentModel.Create`'s existing `endpoint` parameter for symmetry. Enables
  Anthropic-compatible endpoints (Moonshot/Kimi, DeepSeek, Zhipu/GLM) without a separate adapter.
  Purely additive; omitting `endpoint` preserves the SDK's own default.

### Model catalog: three new Current-tier models

- **`claude-opus-5`** (`Models.Anthropic.Opus5`) — Anthropic's new Current-tier model for complex
  agentic coding and enterprise work. `claude-opus-4-8`'s replacement pointer moves from
  `claude-fable-5` to `claude-opus-5` (the direct same-line successor); Fable 5 remains the
  separate top-of-line frontier model.
- **`gemini-3.6-flash`** (`Models.Google.Gemini36Flash`) and **`gemini-3.5-flash-lite`**
  (`Models.Google.Gemini35FlashLite`) — Google's new Current-tier stable models. `gemini-3.5-flash`
  and `gemini-3.1-flash-lite` move to Legacy, replaced by these; `gemini-3.1-flash` and
  `gemini-2.5-flash`'s replacement pointers move from `gemini-3.5-flash` to `gemini-3.6-flash`
  (every `ReplacedBy` must point at a Current model, never an intermediate Legacy one). All three
  registered in both `ModelCatalog`s and `model-lifecycle.json`; see
  `docs/reference/model-deprecations.md` for the full table.

### Mapper coherence tests

- New `ModelMapperCoherenceTests` (`Ananke.Orchestration.Tests`) run two checks against
  `AnthropicModelMapper`, `OpenAIModelMapper`, and `GeminiModelMapper`: an already-native model id
  is never rewritten to a different model, and every id a mapper's cross-provider table can
  produce has a matching `Capabilities` entry. These two checks would have caught a prior mapper
  regression before it shipped.

### Dependency cleanup

- `Microsoft.OpenApi`, `Microsoft.AspNetCore.OpenApi`, and `Scalar.AspNetCore` removed entirely
  (not upgraded) — `AgenticWebDemo` and `PetAdoptionDemo` were the only consumers solution-wide,
  using them only for interactive `/scalar` API docs, not load-bearing to what either demo
  demonstrates. A same-day `Microsoft.OpenApi` 2.7.5 → 3.9.0 bump had broken both demos because
  `Microsoft.AspNetCore.OpenApi` 10.x's own dependency contract requires staying on `Microsoft.OpenApi`
  2.x; the real 3.x upgrade needs `Microsoft.AspNetCore.OpenApi` 11.x, which is `net11.0`-only with
  no stable release yet. Revisit once a stable release lands. If you were hitting either demo's
  `/scalar/v1` endpoint, it's gone — there's no replacement in this release.

### Code-quality fixes

- **`nnke validate` (and 16 sibling commands) now exit non-zero on failures they already report.**
  Previously every command but `serve` returned exit `0` regardless of outcome — `nnke validate
  bad.yml && deploy` would proceed on an invalid manifest. See Breaking changes.
- **`nnke new quickstart`/`chatbox`/`workflow`/`pattern` no longer leak a raw stack trace on an
  invalid project name.** Bad names now get a clean diagnostic; a new top-level handler in
  `Program.cs` catches anything else the same way.
- **Project-name validation now uses an explicit allowlist, not a platform capability query.**
  The original fix (above) checked names against `Path.GetInvalidFileNameChars()`, which returns
  41 banned characters on Windows but only two — `'\0'` and `'/'` — on Unix. That made the guard a
  near no-op on Linux/macOS, and on **every** platform it let `.` and `..` through, since neither
  is on that list: `nnke new quickstart ".."` wrote its files into the *parent* of the target
  directory and reported success. Names are now checked against an explicit allowlist
  (`Ananke.Tool.Shared.ProjectNameValidator`, letters/digits/`.`/`_`/`-`, with `.` and `..`
  rejected outright) so the CLI behaves identically on every platform and enforces the "letters,
  numbers, hyphens, underscores, and periods" hint it already prints. See Breaking changes.
- **`QdrantEmpiricalMemory` no longer drops `EpisodeId`/`StepIndex`.** Skill packages exported from
  a Qdrant-backed memory previously came out with no episodes, silently.
- **`ToolKit` now logs a warning when a tool fails to register in memory**, instead of discarding
  the failure with no trace.
- **The OpenAI, Anthropic, and Gemini adapters now throw instead of silently dropping an
  unsupported content part** (e.g. a `DocumentPart`, or an `AudioPart` sent to Anthropic). See
  Breaking changes.

## Breaking changes

### `AgentResponse.Text` no longer includes reasoning content

**Who is affected:** any code parsing `AgentResponse.Text` from an Anthropic reasoning model
(extended thinking enabled).

**What changes:** previously, Anthropic's `thinking` blocks were prepended to `Text`, contaminating
it with reasoning content ahead of the actual answer. `Text` now contains only the model's response
text — this is a correctness fix, not a behavior to preserve compatibility with. Consumers that were
parsing around the prepended thinking text (stripping a preamble, splitting on a marker) should
remove that workaround; consumers that want the reasoning content should read `ReasoningPart`
entries from `AgentResponse.Parts` instead.

**Migration:** none needed for code that only read `.Text` expecting an answer — it now gets exactly
that. Code that inspected the old value for reasoning content should switch to
`response.Parts.OfType<ReasoningPart>()`.

### `StoreCompletions` now defaults to `false`

**Who is affected:** any host relying on provider-side completion logs (Anthropic/OpenAI/Google
platform logs) for its own audit trail, without having explicitly set `StoreCompletions = true`.

**What changes:** `AgentRequest.StoreCompletions`, `OrchestrationOptions.StoreCompletionsEnabled`,
`Workflow<TState>`'s and `WorkflowRunner`'s equivalents, and — the sites that actually governed
standalone (non-workflow) behavior — the `?? true` fallbacks in `AgentJob`/`TextAgentJob` all now
default to `false`.

**Migration:** if you depend on provider-side completion logs, set `StoreCompletions = true`
explicitly wherever you configure requests, workflows, or the orchestration DI extension.

### `nnke` commands report failure via exit code, not just stdout

**Who is affected:** scripts/CI/hooks calling `nnke validate` (or any other command) that only
checked stdout/`--json` output, not the exit code.

**What changes:** commands that detect and report a failure now exit non-zero instead of always `0`.

**Migration:** none if you already check the exit code, which is what the docs always told you to
do. If you were parsing stdout because the exit code couldn't be trusted, you can now use it.

### Scaffold project names are now restricted to an explicit allowlist

**Who is affected:** anyone piping a project name with spaces, non-ASCII letters, or other
characters outside `[A-Za-z0-9._-]` into `nnke new quickstart`/`chatbox`/`workflow`/`pattern` —
previously accepted on some platforms (inconsistently — see "Code-quality fixes" above), now
rejected everywhere with `ANANKE_IO_002`.

**What changes:** a name must match `[A-Za-z0-9._-]+` and cannot be `.` or `..`. This closes a
real defect, not just a style tightening: the old check let `..` through on every platform,
writing the scaffolded project into the parent of the target directory.

**Migration:** rename to use only letters, digits, hyphens, underscores, and periods — the
diagnostic's hint text has said this from the start.

### Provider adapters throw on an unsupported content part

**Who is affected:** code sending a `DocumentPart`, `ReasoningPart` (request-side), or an
`AudioPart` to Anthropic — previously silently dropped, now a `NotSupportedException`.

**Migration:** remove the unsupported part before sending, or catch and handle the exception. No
internal code path constructs these today, so this should only affect direct, manual construction.
