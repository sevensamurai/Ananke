# Ananke v0.9.3

**Theme: knowledge stores behave the same, and records keep to their passage**

## In short

- **The stores agree.** The in-memory, Postgres and Qdrant knowledge stores now read dates, filters, ids and deletes
  the same way, so code moved from one store to another gets the same results.
- **Deletes are safe.** A delete with an empty filter is refused on every store instead of removing everything (or,
  on Qdrant, nothing). A delete through `LinkedKnowledgeStore` or `CatalogAwareKnowledgeStore` cleans up the links and
  catalog entries of exactly what it removed.
- **Hybrid search can be weighed.** `SearchOptions.DenseWeight` and `KeywordWeight` set how much each half of a
  `Hybrid` search counts, in the in-memory and Postgres stores.
- **Records cite their passage.** A record can be kept only when its quote is found in the document; several record
  types can share one store; people's own records (`DatedRecordWriter<TRecord>`) are kept beside extracted ones when
  the document is indexed again.
- **Linked knowledge works on every store.** `LinkedKnowledgeStore` follows the links of documents indexed through
  `DocumentProcessor`, keeps to the search's filter, can be listed, and, over a store that lists, embeds the query
  once per search.
- **Superseded marks follow the documents.** Deleting a newer document, or indexing it again with fewer
  `replaces_sources`, clears the marks it set, unless another document still replaces the older one.
- **Fixes.** Postgres keyword search under a filter, Postgres table and index names, Qdrant chunk ids and filter keys,
  `InProcessWorkflowHost` pause, stop and dispose, and `MemgraphKnowledgeGraph`'s schema and edge provenance.

## Before you upgrade

Most of these changes are to experimental APIs (`ANNKEEXP004`), but some change what a call does. Check these first;
each is explained under *Upgrading* and *Breaking changes* below.

1. **A delete with an empty filter throws.** Name what to delete (a source, say).
2. **Records stored by 0.9.2 are not deleted on re-index.** Delete each source's records by `source` once before
   indexing the documents again.
3. **Your own `IDocumentRecords` or `IListableKnowledgeStore` doesn't compile.** Add `Owns` and `WritesTo`, change
   `ExtractAsync` to return `(int Stored, int Refused)`, add `UpdateMetadataAsync`.
4. **A records step writing to the processor's own store is refused.** Give records a store of their own.
5. **Postgres names have limits.** A table name of more than 49 characters, or a schema and table of more than 52
   together, is refused.
6. **Qdrant points written before 0.9.3 keep their UUID as id** until their documents are indexed again.

## What's new

### Knowledge
- **Weights for `Hybrid` search.** `SearchOptions.DenseWeight` and `KeywordWeight` (default 1 each) weigh the dense
  and keyword rankings in `Hybrid`'s reciprocal rank fusion: a result at rank `r` of a ranking adds `weight / (60 + r)`.
  A weight of 0 skips that ranking; both 0 throws `ArgumentException`. In `InMemoryKnowledgeStore` and
  `PostgresKnowledgeStore`; Qdrant is unchanged. Which weights rank best depends on the documents: on news articles keyword search alone ranked best, on a product's
  own design documents the default 1 and 1 did, so measure on your own before changing them.
- **`IListableKnowledgeStore.UpdateMetadataAsync(listed, metadata)`** gives a listed chunk new metadata without
  embedding it again, only while it is still stored as it was listed. The in-memory, Postgres and Qdrant stores
  implement it; `EntityScopedKnowledgeStore`, `CatalogAwareKnowledgeStore` and `LinkedKnowledgeStore` pass it through.
- **`LinkedKnowledgeStore` can be listed** (`IListableKnowledgeStore`, through its inner store).
- **`IKnowledgeCatalog.GetReplacingAsync(source)`**: the entries whose `Replaces` names a source. A default interface
  method that browses every entry, so a catalog of your own compiles unchanged; answer it in one query, as the
  Postgres, Qdrant and in-memory catalogs do.
- **`IKnowledgeCatalog.GetManyAsync(sources)`**: the entries of several sources in one call. A default interface
  method (one `GetAsync` per source); the built-in catalogs answer it in one query or request.
- **`KnowledgeDateOrder.ReadDate`** reads a date as the stores do when they list by date (see *Upgrading*).
- **`KnowledgeFilter.Copy()`**: a new filter with the same entries and `AnyOf`.

### Records
- **A record cites its passage.** With `DatedRecordOptions<TRecord>.Quote` set, a record is stored only when its quote
  is found in one section of the document, ignoring case and runs of whitespace. The quote and its section's title are
  kept as `quote` and `section` metadata, and `DatedRecord<TRecord>` gains `Quote` and `Section` (optional, after
  `Score`). `ProcessingResult.RecordsRefused` counts the records read but not stored (quote not found, or refused by
  `Keep`).
- **Several record types in one store.** `DatedRecordOptions.RecordType` names an extractor's type: its records get ids
  `{source}:record:{type}:{n}` and `record_type` metadata, and it deletes only its own. `CompositeDocumentRecords`
  gives `DocumentProcessor.Records` several steps, and `DatedRecordReader` takes an optional `recordType` (a trailing
  optional constructor parameter). An extractor without `RecordType` stores and deletes as before.
- **Records people write.** `DatedRecordWriter<TRecord>` stores records with no model call (people's notes) beside
  extracted ones, marked `written`. Given to `DocumentProcessor.Records`, it checks their quotes each time the document
  is indexed and marks a record `passage_gone` (`DatedRecord.PassageGone`, and `list_records` says so) while its quote
  is gone from the document. The mark is set through `UpdateMetadataAsync`, so a record written again or erased while
  its document is indexed keeps that write or stays deleted, and a mark change doesn't embed the record again.
- **`DatedRecordOptions.Instructions` is no longer required** (the extractor still refuses a blank one).

## Upgrading

### Knowledge
- ⚠ **A delete with an empty filter throws.** `IKnowledgeStore.DeleteAsync` with an empty `KnowledgeFilter` (no
  entries, no `AnyOf`) now throws `ArgumentException` on every store (in-memory, Postgres, Qdrant, and through
  `CatalogAwareKnowledgeStore`, `EntityScopedKnowledgeStore` and `LinkedKnowledgeStore`) and deletes nothing. It used
  to remove everything on the in-memory and Postgres stores (and every document of the entity through
  `EntityScopedKnowledgeStore`), and nothing on Qdrant. Name what to delete, by source for instance.
- ⚠ **`id` in a filter is the chunk's id on every store.** An `id` entry, or `id` in `AnyOf`, matches the chunk's id,
  so a metadata key named `id` is no longer matched by it.
- ⚠ **A delete through the wrapping stores cleans up what it removed.** Over a store that lists,
  `LinkedKnowledgeStore.DeleteAsync` now also removes the links of chunks deleted by a filter that names no id (a
  source, say), and keeps those of named ids another key kept; `CatalogAwareKnowledgeStore.DeleteAsync` keeps a
  source's catalog entry while a narrowed delete (a page as well as a source) leaves chunks of it. A product that
  removed links itself after deleting a source no longer needs to. Over a store that can't list, both behave as
  before. `LinkedKnowledgeStore`'s delete reads the matching chunks once and removes their links before the chunks; a
  delete naming only ids removes those ids' links without listing, whether the chunks are stored or not.
- ⚠ **A date without an offset is read as UTC.** An `effective_at` (or any `KnowledgeDateOrder` key) such as
  `2026-11-01T00:00:00` was read in the process's local time zone by `InMemoryKnowledgeStore`, `DatedRecordReader`,
  `LinkedDocumentReader` and `CatalogAwareKnowledgeStore`, and in the session's time zone by
  `PostgresKnowledgeStore`, while Qdrant read it as UTC, so `since` and the order could differ by store. Every store
  and reader now reads it as UTC. Dates Ananke writes carry an offset and read as before; a date written by other
  code without one now reads as UTC, so give it an offset if it meant local time. A catalog entry's date was read
  from its chunks when indexed, so on a server not on UTC, index such a document again to bring its entry's date in
  line.
- ⚠ **Listing by date reads only ISO 8601 dates.** Listing with a `KnowledgeDateOrder`, and `DatedRecordReader`, read
  only `yyyy-MM-dd[THH:mm[:ss[.fffffff]][Z|±hh[[:]mm]]]` (an offset, after a time, of at most 14 hours) in `InMemoryKnowledgeStore` and
  `PostgresKnowledgeStore`; `infinity`, `epoch`, `today`, `03/04/2026` and the like are no date and list after the
  dated chunks. Qdrant's datetime index still reads a few other forms, named in `KnowledgeDateOrder`'s remarks.
- ⚠ **`LinkedKnowledgeStore` follows a link only to a chunk the search's filter matches.** With `ExpandGraph`, a linked
  chunk was looked up by its id alone, so a search filtered to one outlet could return a linked chunk of another. The
  lookup now keeps the caller's filter, its entries and `AnyOf`, and a link to an id the filter excludes is not
  followed. A search with no filter expands as before.
- **`LinkedKnowledgeStore` follows links on every store.** It now follows links for documents indexed the usual way
  (through `DocumentProcessor`). It reads a followed link by id through the inner store's listing (one listing per
  seed, within the caller's filter), so the query is embedded once per search; through a `CatalogAwareKnowledgeStore`
  the linked chunk is marked (`effective_at`, `superseded_by`) and, under `SupersededResults.Exclude`, left out when
  superseded. Over a store that can't list, the lookup searches with the caller's options, its `Mode` included. A
  linked chunk unlike the query (negative cosine) is no longer dropped.
- **Superseded marks follow the documents that still replace them.** `CatalogAwareKnowledgeStore.DeleteAsync` of a
  document removes the `SupersededBy` its `replaces_sources` put on the documents it replaced, so they come back
  current in search, unless another document still replaces one: it then stays superseded by that one (the newest).
  A document indexed again with fewer `replaces_sources` clears its mark on the sources it dropped. A mark a
  document's own header gives (its chunks' `superseded_by`) stays. Telling the two apart lists the older document's
  chunks: over a store that can't list, the marks stay as before.
- **A catalog-aware search reads the catalog once per round of results.** `CatalogAwareKnowledgeStore.SearchAsync`
  reads the entries of all its results' sources in one call to `IKnowledgeCatalog.GetManyAsync`, instead of one
  `GetAsync` per source; `DatedRecordReader` reads its records' sources the same way. A test double of
  `IKnowledgeCatalog` (NSubstitute, Moq) set up only for `GetAsync` answers `GetManyAsync` with nothing, so its results
  are no longer marked: set up `GetManyAsync` too.

### Records
- ⚠ **Extracted records are marked, and only those are replaced.** An extracted record now carries `extracted=true`
  metadata, and `DatedRecordExtractor` deletes only those when its document is indexed again. Records stored by an
  earlier version have no such mark and aren't deleted by it, so delete each source's records by `source` once before
  indexing again. An extractor given a `RecordType` doesn't delete the records it stored without one either.
- ⚠ **`IDocumentRecords` (experimental) has new members and a new return type.** `ExtractAsync` returns
  `Task<(int Stored, int Refused)>` instead of `Task<int>` (an implementation of your own returns `(stored, 0)`).
  `Owns` names the store and record type a step replaces (return `[]` for a step that deletes no records), and
  `WritesTo` every store a step writes to.
- ⚠ **`ProcessingResult` has a sixth parameter.** Its positional constructor and `Deconstruct` gain `RecordsRefused`
  (default 0); a deconstruction into five variables needs a sixth.
- ⚠ **`DatedRecord<TRecord>` has three more parameters.** Its positional constructor and `Deconstruct` gain `Quote`,
  `Section` and `PassageGone` (optional, after `Score`); a deconstruction into eight variables needs eleven.
- ⚠ **Records steps that would delete each other's records are refused.** `CompositeDocumentRecords` throws
  `ArgumentException` for an extractor with no `RecordType` beside another extractor on its store, or two extractors
  with the same `RecordType` on one store. A store reached through `LinkedKnowledgeStore` or
  `CatalogAwareKnowledgeStore` counts as the store they decorate, so such steps over a wrapper and its inner store are
  refused too.
- ⚠ **Records need a store of their own.** `DocumentProcessor.Records` throws `ArgumentException` when a records step
  writes to the processor's own store (directly or through `LinkedKnowledgeStore` or `CatalogAwareKnowledgeStore`),
  where each indexing deleted its records.

### Postgres
- ⚠ **Table names over 49 characters are refused.** `PostgresKnowledgeStore` keeps its keyword-search counts in
  `<table>_lexemes` and `<table>_lexemes_count`, and Postgres cuts names at 63 bytes, so a longer table name made
  these collide with each other or with the table. The constructor (of `PostgresKnowledgeCatalog` too, which checks
  its table the same way) now throws `ArgumentException` for a name (without its schema) of more than 49 characters;
  rename the table or choose a shorter `PostgresKnowledgeOptions.Table`.
- ⚠ **A schema and table of more than 52 characters together are refused.** `PostgresKnowledgeStore` and
  `PostgresKnowledgeCatalog` throw `ArgumentException` for a schema-qualified `Table` whose schema and table together
  pass 52 characters (without the dot): its index names, `<schema>_<table>_embedding` and the like, would pass 63 and
  be cut, and the keyword (`tsv`) and metadata GIN indexes were silently skipped. A table already that long: move it
  to a shorter schema or table name, and index its documents again.
- **`Hybrid` holds two connections.** It runs its dense and keyword queries at the same time, each on a connection of
  its own, so one search holds two of the data source's pooled connections at once: a pool sized for one connection
  per search serves half as many hybrid searches at a time.
- **Keyword search under a filter falls back in steps.** When a filter keeps no row holding a rare query term (or,
  with none rare, every term), the rows it keeps holding every term some kept row holds are scored, and then rows
  holding any query term, where it returned none. Rows holding only common words (*the*, *is*) no longer fill the
  results. Without a filter: rare terms, else all terms, as before.
- **Listing by date needs PostgreSQL 16 or later.** `PostgresKnowledgeStore.ListAsync` with a `KnowledgeDateOrder`
  (which `DatedRecordReader` and `list_records` always pass) uses `pg_input_is_valid`, added in PostgreSQL 16. On an
  earlier server it now throws `NotSupportedException` naming 16 and the server's version, instead of failing with
  `function pg_input_is_valid does not exist`. Search, writes and listing without an order are unchanged.

### Qdrant
- ⚠ **`KnowledgeChunk.Id` is the document id.** `QdrantKnowledgeStore` returns a chunk's id as it was upserted
  (`{source}:record:{n}`), as the in-memory and Postgres stores do, not the point's UUID. It keeps the id in an `_id`
  payload field (so `DatedRecord.Id` and `list_records`' "replaced by" show it). A point written before 0.9.3 has no
  `_id` and is returned with its point UUID as before; index those documents again to get their ids back.
- **Filters on any metadata key.** A `KnowledgeFilter` key holding a character other than a letter, digit, `_` or `-`
  (a document link such as `entity:document:notes/a.md`) was refused by Qdrant as an invalid path, so asking which
  documents link to one failed; `QdrantKnowledgeStore` now matches it as one field, as the other stores do, in a
  filter and in a `KnowledgeDateOrder`. Qdrant still refuses a key holding `"` or `\`.

### Organics
- ⚠ **`InProcessWorkflowHost` after dispose.** `StartAsync` during or after `DisposeAsync` throws
  `ObjectDisposedException`. `DisposeAsync` and `StopAsync` wait for a paused cell's loop to unwind; a `PauseAsync`
  whose token fires leaves the cell paused, settling once its loop ends; a loop that crashes or returns on its own
  while being paused leaves `ListActive`.

### Graph
- **`MemgraphKnowledgeGraph` works on Memgraph.** `EnsureSchemaAsync` no longer fails (its indexes were created in an
  explicit transaction, which Memgraph refuses), and `UpsertEdgeAsync` no longer demotes an edge's provenance (it kept
  the higher ordinal, so `Inferred` replaced `Extracted`). Its tests now run against `memgraph/memgraph-mage` in
  Testcontainers.

### Building Ananke
- **The default test run starts no containers.** The Redis, MQTT, Qdrant, Postgres and Memgraph adapter tests are in
  the category `Containers` and explicit; `bash scripts/ci.sh --containers` runs them, and fails when any of them was
  skipped.

## Breaking changes

Each is explained under *Upgrading*.

- `IKnowledgeStore.DeleteAsync` with an empty filter throws `ArgumentException` on every store.
- `id` in a `KnowledgeFilter` is the chunk's id on every store, not a metadata key.
- A delete through `LinkedKnowledgeStore` or `CatalogAwareKnowledgeStore` removes the links and catalog entries of
  exactly what it deleted, and keeps a source's catalog entry while chunks of it remain.
- A date without an offset is read as UTC; listing by date reads only ISO 8601 dates.
- `LinkedKnowledgeStore` follows links only to chunks the search's filter matches.
- Extracted records carry `extracted=true`, and only those are replaced; records stored before 0.9.3 are not deleted
  on re-index.
- `IDocumentRecords.ExtractAsync` returns `Task<(int Stored, int Refused)>`; `IDocumentRecords` gains `Owns` and
  `WritesTo` (experimental).
- `ProcessingResult` gains a sixth positional parameter, `RecordsRefused`; `DatedRecord<TRecord>` gains `Quote`,
  `Section` and `PassageGone` after `Score` (experimental).
- `IListableKnowledgeStore` gains `UpdateMetadataAsync` (experimental): a store of your own implementing it must add it.
- `CompositeDocumentRecords` and `DocumentProcessor.Records` refuse records steps that would delete each other's
  records or that write to the processor's own store.
- Postgres table names over 49 characters, and schema and table over 52 together, are refused.
- `QdrantKnowledgeStore` returns the upserted id as `KnowledgeChunk.Id`, not the point UUID.
- `InProcessWorkflowHost.StartAsync` during or after `DisposeAsync` throws `ObjectDisposedException`.
