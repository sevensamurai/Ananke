# Ananke v0.8.6

**Theme: conversational workflows, multi-label knowledge graphs, and a documentation drift guard**

This release adds a new workflow control-flow primitive (declarative loops) and a full
conversational-interview pattern on top of it, makes the knowledge graph multi-label aware, and
ships a dependency-free script that catches stale type/API names in Markdown before they reach a
PR — plus the navigation overhaul and drift fixes that script's first run surfaced.

---

## What's new

### Declarative loops & conversational (interview) workflows

Two related control-flow gaps in the workflow layer, closed together:

**Part A — `loop()` reaches the declarative layer.** `Workflow<TState>.Loop(...)` already existed
at runtime, but the DSL/`WorkflowScaffold` that authors topology from `.ananke.yml` had no way to
declare it — any manifest-loaded workflow needing iteration had to drop back to a code factory.

```
await_ci -> loop(code-cycle, exit: report_to_slack)
await_ci -> loop(code-cycle, exit: report_to_slack, maxIterations: 25)
```

- `ConnectionLine.Loop` + `WorkflowDslParser` support for the `loop(target, exit:, maxIterations:)` syntax.
- `WorkflowScaffold<TState>.BindLoopCondition(from, until)` binds the `until` predicate in code
  (consistent with `BindMerge`/`BindRouter` — behavior stays in code, structure stays in YAML);
  `UnboundLoops` reports anything not yet bound.
- `WorkflowManifest.Connections` needed no change — `loop(...)` passes through as a raw DSL line.

**Part B — conversational (interview) workflows**, built entirely on existing primitives (no new
execution engine):

- **`ask(node)` DSL marker / `Workflow<TState>.AwaitInput(node)`** — pauses before a job exactly
  like `InterruptBefore`, plus records it in the new `WorkflowDefinition.InputJobs` set, so a host
  can tell an input-collecting turn apart from a plain approval gate.
- **`AgenticPattern.Interview<TState>`** — a new pattern builder (alongside `ReviewCritique` and
  `IterativeRefinement`) assembling welcome → icebreaker → a turn loop over a question agenda held
  in state. `WithQuestion`/`WithNavigation` select the next prompt and fold expand/skip/update
  navigation; because the user's reply only exists at resume time, `Build()` returns an
  `Interview<TState>` carrying the workflow **plus** two host-side hooks, `GetQuestion` and
  `FoldAnswer`, rather than a bare `Workflow<TState>`.
- **`WithMemory(memory, conversationId)`** writes every turn (question + answer) to
  `IConversationMemory` automatically.
- **`WithTurnTimeout(timeout)`** exposes `Interview<TState>.PauseMessage`/`TurnTimeout` for a host
  to show a "no rush — reply whenever" note on a quiet turn. The framework runs no timer itself —
  a turn that times out stays checkpointed and resumable, never aborted.
- **`WorkflowInputExtensions.ResumeWithInputAsync`** — a channel-agnostic helper that folds a
  reply into state and resumes in one call, so a platform adapter only has to correlate the
  inbound message to the execution id.

The worked-example demo for this pattern (a recruit-onboarding interview exercising expand, skip,
and update navigation end-to-end, keyless) lives outside this repository in a sibling
`PoC-interview` project that references this codebase directly — new demos are being kept out of
the open-source tree going forward to keep it lean; see "Demos" below.

### Multi-label support for `GraphNode`

`GraphNode` gains an additive `Labels` property and a computed `EffectiveLabels` view
(`Kind` always first, followed by `Labels` deduplicated against it) — a node that never sets
`Labels` behaves exactly as before.

- `MemgraphKnowledgeGraph.UpsertNodeAsync` applies `EffectiveLabels` (beyond the structural
  `:Node` label) as real Cypher labels via a new `SET n:Label1:Label2…` statement, validated by a
  sibling `ValidateNodeLabel` (PascalCase, `"Node"` reserved). Reads reconstruct `Labels` from the
  driver's `INode.Labels`, dropping the literal `"Node"` entry.
- `ICentralityScorer.ScoreAsync`'s `nodeKindFilter` now matches against `EffectiveLabels` instead
  of just `Kind` — a strict superset of the old behavior — across `PageRankCentralityScorer`,
  `DegreeCentralityScorer`, and `MemgraphPageRankScorer`.

### Documentation drift guard + LLM navigation

A local, dependency-free pre-PR check: build a symbol set from `src/**/*.cs` (comments stripped),
scan inline `` `code` `` spans (plus fenced blocks in every `ARCHITECTURE.md`, since those *are*
the curated type inventory) for backtick-quoted identifiers, and flag any that exist nowhere in
source — exactly the failure mode that let a renamed `GoogleAgentModel` → `GeminiAgentModel` hide
in prose for a release or more.

- `scripts/check-docs.ps1` + `scripts/check-docs-ignore.txt` (allow-list for genuine externals)
  + `scripts/README.md`.
- `MAP.md` — a single concept → architecture-doc → guide → source-dir routing table, so "where do
  I read about X" has one answer instead of several drifting lists.
- Per-package `ARCHITECTURE.md` gained a "Start Here" section (curated entry-point types with
  source paths) across ~20 packages, and `src/ARCHITECTURE.md` / root `ARCHITECTURE.md` were
  extended with the federation/tooling layers that had grown undocumented.
- Running the guard for the first time found and fixed real drift: `Ananke.StateMachine`'s
  `ARCHITECTURE.md` described a since-replaced `StateMachine<TState,TAction>` / `Configure().On().TransitionTo()`
  shape — the actual code (`StateMachine.Create<S,T>`, `.From().On().To()`, `FireAsync`) had moved
  on without the docs; `MiddlewareAgentModel`'s pipeline diagram still named `OpenAIAgentModel`/
  `GoogleAgentModel` instead of `OpenAIChatAgentModel`/`GeminiAgentModel`; a stale `TrustScale`
  reference in `docs/faq/memory.md`; and a duplicate `docs/guides/nnke-platform-tool.md` was
  removed in favor of the canonical `docs/cli/nnke-platform-tool.md`.

### New model identifiers

`Models.Anthropic` and `ModelCatalog` gain entries for the current Claude generation:
`Opus48` (`claude-opus-4-8`, frontier reasoning), `Sonnet46` (`claude-sonnet-4-6`, balanced), and
`Haiku45` (`claude-haiku-4-5`, fastest — no extended reasoning, by design).

### Demos: `CodingAgencyDemo` moved out of the repository

The Slack-integrated coding-agency demo (plan → code-cycle → CI loop → review → report)
now lives in a sibling `PoC-agency` project that references `Ananke.Orchestration`
et al. directly from this working tree, rather than as a project inside this solution. It builds
and runs identically; nothing in its code changed beyond the `ProjectReference` paths. This keeps
demo iteration decoupled from the framework's own release cadence without losing the ability to
build against in-progress framework changes.

### Smaller fixes

- `CliProcessRunner.RunAsync` gains an optional `workingDirectory` parameter (see Breaking changes).

## Breaking changes

### `CliProcessRunner.RunAsync` — new parameter inserted before `timeout`

```csharp
// Before
Task<CliProcessResult> RunAsync(string fileName, string arguments, TimeSpan? timeout = null, CancellationToken ct = default);

// After
Task<CliProcessResult> RunAsync(string fileName, string arguments, string? workingDirectory = null, TimeSpan? timeout = null, CancellationToken ct = default);
```

**Who is affected:** any caller passing `timeout` or `ct` **positionally** (e.g.
`RunAsync(file, args, myTimeout, myCt)`) — the third positional slot is now `workingDirectory`
(`string?`), so a `TimeSpan?` argument there fails to compile.

**Migration:** pass `timeout`/`ct` by name, e.g. `RunAsync(file, args, timeout: myTimeout, ct: myCt)`,
or supply `workingDirectory` explicitly. The one in-repo call site (`Ananke.Skills.OpenClawCatalog`)
is already updated.
