# Ananke v0.9.0

**Theme: enterprise cloud surfaces, and honesty about small and self-hosted models**

Amazon Bedrock and Microsoft Foundry now reach through the adapters already in the tree, with every
adapter under a published conformance suite. Local and self-hosted models get a catalogue you can
query for size, licence and weights, a context window that reflects what the server actually serves,
and a routing hazard that now says something instead of failing silently. The plan tier also gets
several improvements: a plan can be authored as well as run, re-ruled without wiring an executor by
hand, and rendered for a person; a few fixes land in the streaming and retry paths alongside it.

> **On "small language models".** This release does not claim general SLM support. It adds honesty
> *about* them — a catalogue you can query, a context window that reflects the server rather than the
> weights, and a routing hazard that now says something. It does **not** add a runtime that refuses
> what a deployment cannot do.

---

## What's new

### Enterprise clouds

- **`Ananke.Orchestration.Bedrock`** (new package) — Amazon Bedrock, auth and endpoint construction
  only. SigV4 and Bedrock API-key auth; `BedrockAgentModel.CreateChatCompletions`/`.CreateMessages`
  return the ordinary `OpenAIChatAgentModel`/`AnthropicAgentModel`, so there's no third wire format
  and no Bedrock-specific model type. Deliberately no model catalogue — ids churn by region and
  version — so Bedrock ids sit outside `ModelCatalog.Validate` and the deprecation analyzers.
- **Microsoft Foundry** needs no new package — its Azure OpenAI-compatible endpoint is served by the
  existing OpenAI adapter, confirmed against a live deployment.
- **`Ananke.Orchestration.Conformance`** + **`.Conformance.NUnit`** (new packages) — 28 scenarios
  every shipped `IStreamingAgentModel`/`IToolSchemaTranslator`/`IJsonSchemaTranslator` adapter must
  satisfy, self-validated against reference subjects. A coverage test fails the build if a shipped
  adapter has no fixture.
- **`azure-ai` is renamed `azure`** (`foundry` remains an alias of both) — platform identifiers are
  aliased, never replaced, so nothing that stored the old name breaks.

### Local and self-hosted models

- **Model classification** — `ModelClassification` (size class, parameter count, weights, licence
  SPDX/OSI status, family) on every catalogue template and profile, kept out of `ModelCapability` so
  it can never affect routing. Query via `ModelCatalog.SmallModels`/`.LicensedUnder(...)`, or filter
  routing itself with `CapabilityModelRouter.WithPolicy(predicate)`.
- **Catalogue coverage** — Microsoft Phi and Alibaba Qwen are new families; Mistral gains Ministral
  3B/8B; Gemma gains a template.
- **The effective context window is now visible.** `LocalDeployment` records what the server was
  actually launched with; `ModelProfile.ContextTokens` reports that instead of the catalogue's rated
  `MaxContextTokens`, so routing can no longer say "fits" on a window the runtime silently truncated.
- **Zero-cost routing no longer wins silently.** `CheapestFit` still means cheapest — that's
  unchanged — but the router now logs once per model when a free local profile displaces a paid
  candidate that also qualified.
- **A local `endpoint:` no longer demands an API key.** `ModelResolver` checks the endpoint before
  the key and supplies a placeholder when none is configured; a configured key still always wins.
- **A live test tier for self-hosted models**, needing no account and no money — opting into it
  should not opt you into the billed tiers. Skips with a stated reason when no server answers.
- **New guide:** [17 — Local & self-hosted models](../docs/guides/17-local-models.md), consolidating
  guidance that was spread across six pages. **Nothing records which endpoint served a request** —
  `LocalDeployment.ServedBy` is what you configured, not a runtime attestation.

### The plan tier

- **A plan runs as an ordinary job** — `Supervise` registers it the way `SubFlow` registers a nested
  workflow, no control loop or store to wire by hand. A disputed node halts and hands the decision
  back rather than resolving it inline.
- **A plan can be written, not just read** — `PlanManifest.ToYaml` (`Ananke.Design`) round-trips by
  value; anything that couldn't come back unchanged (a blank line, a `#`-led line, a blank goal) is
  refused at write time instead of shipping a file that reads back wrong.
- **`PlanNarrator`** turns the event stream into readable lines without a hand-written switch;
  **`PlanReportExporter`** renders a tree's current outline or its full version-by-version lineage,
  each diffed against the version before it rather than read from an annotation.
- **Re-ruling a plan needs no executor** — `SupervisionOptions.ReruleAsync` and
  `PlanRevisionManifest.ApplyToAsync` do it under the supervision already in hand.
- **Two deterministic gates ship at last** — `ProcessCheck` and `PredicateCheck` implement
  `IDeterministicCheck`, which shipped in an earlier release with nothing behind it. Both refuse
  criteria they weren't given, and a check that fails to run throws rather than reporting `false`.
- **Rate limits are waited out for as long as the provider says**, not on a fixed exponential curve —
  capped at two minutes so a daily quota fails fast instead of hanging.
- **What a step is handed when it proposes a change** — an operation's legend can now show a worked
  example, not just its name; `PlanNodeReport` and `Operation` carry `[Description]` so their meaning
  reaches the model through the schema instead of prompt prose alone; a computed property no longer
  leaks into the generated response schema. `PlanNodeReport.Done` still means two different things
  depending on whether a step reports or proposes — unchanged behaviour, now documented on the type.
- **The operation seam has a conformance suite too** — nine scenarios covering what an
  `OperationCatalog`/`PlanCandidateApplier` pair must satisfy, self-validated the same way the
  provider suite is. **Source only for now, not published** — nothing outside this repository
  consumes it by package yet.

### Workflow streaming

- **Work below a job can report progress, and a `SubFlow`'s events reach the caller.**
  `WorkflowEventReporting` is an ambient sink — a job reports without knowing a channel exists, and
  a nested workflow's events now arrive on the outer stream instead of vanishing.

## Breaking changes

**`PlanReferral` and `PlanOption.Referral` are removed.** An advisor option now only gives the step
up (`Abandon`) or asks for a replan (`Replan`) — never a contract of its own. `PlanDecision.ReplanPlan.Contract`
is nullable; `null` means the Planner writes the change. `PlanOption.Contract`/`.NodeId` are removed
with it.

**`StreamAsync` now yields `WorkflowEvent`, not `WorkflowEvent<TState>`.** A stream can carry events
from more than one state type. Pattern matching (`case JobCompleted<MyState> jc:`) is unaffected;
update explicit annotations (`List<WorkflowEvent<T>>` → `List<WorkflowEvent>`) and generic helper
calls (`OfType<TState, TEvent>` → `OfType<TEvent>`). `PlanNodeAgentOptions.OnReport` is gone — handle
`PlanNodeReported` on the stream instead. `PlanNodeContext` gained two required members, `PlanId` and
`PlanVersion`.

Otherwise additive, with two behaviour changes worth knowing: a manifest with an `endpoint:` and no
API key now resolves instead of throwing, and a `SubFlow`'s inner events now appear on the caller's
stream (distinguish them by `WorkflowName`/`ExecutionId`). No `Ananke.Abstractions` surface changed.
