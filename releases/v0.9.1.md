# Ananke v0.9.1

**Theme: fewer packages, and the plan tier marked as still moving**

0.9.1 stops shipping the packages that nothing in use depends on and that have never run against the
service they target. Every published version of each is deprecated on nuget.org, and each has a
replacement below.

## What's new

- **Keyword and hybrid search in memory.** `InMemoryKnowledgeStore` searches by the mode asked for:
  `SearchMode.Sparse` ranks by BM25 over the documents' terms, and `SearchMode.Hybrid` fuses that ranking with
  cosine similarity by reciprocal rank. Terms keep inner dots and hyphens (`Core.Identity`, `oauth2-proxy`).
  `Dense` is unchanged.
- **Questions that span documents.** `SearchOptions.MaxPerSource` keeps at most that many results from one
  document, and `JoinPerSource` joins a document's passages into one result, so `TopK` counts documents. The
  in-memory, Postgres and Qdrant stores rank more candidates to fill `TopK` (`SearchResultLimits`, experimental:
  `ANNKEEXP004`). On the MultiHop-RAG benchmark (200 sampled questions), three joined passages per document took
  answers from 66.5% to 76% correct, comparisons from 46% to 66%.
- **An embedder says which model it is.** `IEmbeddingModel.Identity` returns an `EmbeddingModelIdentity`
  (provider, model, dimensions, revision), so a store can tell vectors from another model apart.
  `OpenAIEmbeddingModel.Create`, `GeminiEmbeddingModel` and `InMemoryEmbedder` fill it in; an
  `OpenAIEmbeddingModel` made from an `EmbeddingClient` alone, and any other embedder, return
  `null` until they do.
- **Local embeddings: `Ananke.Embeddings.Onnx`** (new package, experimental: `ANNKEEXP004`).
  `OnnxEmbeddingModel` runs a BERT-style ONNX model on ONNX Runtime from a directory the host gives,
  with `[CLS]` or mean pooling, so text needn't leave the host to be embedded. Its vectors for
  bge-small-en-v1.5 match fastembed's to within 1e-8.
- **Knowledge in Postgres: `Ananke.Postgres`** (new package, experimental: `ANNKEEXP004`).
  `PostgresKnowledgeStore` and `PostgresKnowledgeCatalog` keep chunks and catalog entries in
  PostgreSQL with pgvector: `Dense` search by cosine distance, `Sparse` by full-text search,
  `Hybrid` fusing both, `jsonb` metadata filters and deletes that remove rows. Each table records
  its embedder's identity and refuses another.
- **A spending limit on model calls made directly.** `model.WithSpendingLimit(limit)` (experimental:
  `ANNKEEXP004`) adds up each call's cost, tokens and replies cut at their output limit, against a
  `SpendingLimit` any number of models share. Once one is reached, the next call is refused with
  `SpendingLimitExceededException`, which `TerminalProviderError.Is` reads as terminal. A workflow's
  `WithBudget` is unchanged.
- **A document's header, at ingestion.** `DocumentProcessor.Headers` (experimental: `ANNKEEXP004`)
  reads a document's fields and keeps the ones named in `Fields` — none by default — at the top of
  every chunk and in its metadata. Readers for the common shapes: `DocumentHeaders.FromFrontMatter`
  (YAML front matter), `FromFieldBlock` (RFC-822 lines, as PEPs write them), `FromStatusSection` (a
  `## Status` section and a `Date:` line), `FromMarkdown` (`# Title`, `**Key:**` and `**Key**:`), and
  `Combine` to try several. `FromMarkdown` reads the second section when the first has no fields. Tags given to
  `ProcessAsync` fill fields the document doesn't give, and are still written to every chunk. The
  date field becomes `effective_at`, read in the shapes `DocumentHeaders.DateIn` knows (`2026-11-02`,
  `05-Jul-2001`, `July 5, 2001`, `June 2022`) or by `ParseDate`; a catalog keeps it as
  `CatalogEntry.EffectiveAt`. `DropSections` leaves sections out by heading, and `CleanText` cleans
  each section before chunking.
- **Time decay counts a document's age from its own date.** `CatalogAwareKnowledgeStore` ranks by
  `CatalogEntry.EffectiveAt` when there is one, and by `IndexedAt` otherwise. The Qdrant and Postgres
  catalogs store it.
- **Dated records from documents.** `DatedRecordExtractor<TRecord>` (experimental: `ANNKEEXP004`), given
  to `DocumentProcessor.Records`, reads typed records — decisions, say — from each document with one
  call held to the record type's JSON schema, and keeps them in a store of their own with their source
  and date, replaced when the document is indexed again. `ProcessingResult.Records` counts them.
- **Superseding, said either way.** A document's own header can say what supersedes it
  (`DocumentHeaderOptions.SupersededBy`), and a newer document can say what it replaces (`Replaces`), as
  published documents that never change must. `CatalogAwareKnowledgeStore` marks each replaced source's
  catalog entry superseded, whichever is indexed first, and keeps the mark when the older document is
  indexed again. `Updates` are kept apart, as links of kind `updates`. `CatalogEntry.Replaces` lists
  what a document replaces; the Qdrant and Postgres catalogs store it.
- **Which records are current.** `DatedRecordReader<TRecord>` returns records newest first, each with
  `ReplacedBy` set when its document is superseded (by its header, or, given the catalog, by a newer
  document), or a newer record returned with it names it in its `replaces`. Nothing is matched by
  similarity.
- **Lists, not only searches.** A store that implements `IListableKnowledgeStore` (experimental:
  `ANNKEEXP004`; the in-memory, Postgres and Qdrant stores, passed through by the scoped and
  catalog-aware stores) lists every chunk whose metadata matches a filter. `DatedRecordOptions.Fields`
  keeps a record's properties as metadata, `DatedRecordReader.ListAsync` lists records by them, newest
  first, and `DatedRecordTools` gives agents `list_records`.
- **Documents listed by a header field.** `CatalogEntry.Fields` holds the header fields ingestion kept;
  `CatalogBrowseOptions.Field` and `Value` filter by one, and `Order = CatalogBrowseOrder.EffectiveAt`
  lists newest first by the document's own date. The Qdrant and Postgres catalogs store them.
  `KnowledgeCatalogTools` adds a `list_documents` tool.
- **Links by pattern.** `DocumentProcessor.LinkPatterns` and `DatedRecordOptions.LinkPatterns`
  (experimental: `ANNKEEXP004`) take patterns by kind (`card` → a pattern for card keys) and write each
  match in a chunk's or record's text as `entity:{kind}:{match}` metadata, with no model call. A store
  can filter on them, and `DocumentStructureBuilder` turns them into `mentions` edges.
- **Why a reply stopped.** `AgentResponse.StopReason` (`AgentStopReason`: `EndTurn`, `ToolCalls`,
  `MaxTokens`, `ContentFilter`, `Refusal`, `Unknown`) is mapped by the OpenAI, Anthropic and Gemini
  adapters on both paths, and `AgentRequest.MaxOutputTokens` sets the reply's limit on all three.
- A supervised plan whose role models are cost-resolving routers accepts a budget with no flat rates;
  each call is priced at its own model's rate.
- `Models.Anthropic.Sonnet55`, `Opus55` and `Fable51` (`claude-sonnet-5-5`, `claude-opus-5-5`,
  `claude-fable-5-1`), in both model catalogues.
- `StreamingChatWorkflow.Builder.WithToolOutputPolicy` caps tool results on the chat path, as agent
  jobs already could. Off unless set.
- `StreamingChatWorkflow` compacts against the answering model's real window, as agent jobs do, and
  reports a call to a tool the kit does not have to the kit's `IHallucinationObserver`. The reply the
  model gets for one now reads *"Unknown tool 'x': this tool is not registered. Do not call it
  again."*, the same as on an agent job.
- **Usage as metrics.** Every model call publishes the tokens it used on the `Ananke.Orchestration.Usage`
  meter (`ananke.usage.tokens.in`, `ananke.usage.tokens.out`), and a call a cost-resolving router
  prices publishes its cost (`ananke.usage.cost`). Each carries a `workflow` tag naming the run that
  made it. Names are in `UsageInstrumentNames`; export the meter with
  `AddMeter(Sources.OrchestrationUsage)`. `OpenTelemetryBudgetMeter` (`AddBudgetMeter()`) now reads
  these, per workflow.
- **An injectable clock wherever a stamp or an age is read.** `WithTimeProvider` on the `AgentJob` and
  `TextAgentJob` builders (trajectory snapshots, unknown-tool reports, a provider's stated retry
  moment); a `Clock` on `OrganicGrowthOptions`, `DivisionOptions`, `StateMachineOptions` and
  `TagImportanceOptions`; an optional `TimeProvider` on `ToolPruner`, `WorkflowExecutionMonitor`,
  `InMemoryCapabilityMap`, `InMemoryMeshAggregator`, `ColonyReportExporter`, `RememberedPlanTerms`,
  `SkillPackager`, `CatalogAwareKnowledgeStore`, `MemgraphKnowledgeGraph`, the graph builders
  (`DocumentStructureBuilder`, `EpisodeTrajectoryBuilder`, `TagCoOccurrenceBuilder`,
  `ColonyGraphBuilder`), the five division approval gates and `EmpiricalMemoryTools.Create`; an optional
  clock on `DivisionApproval.Approve`, `Reject` and `Revise`; `TimeDecay.Apply` with a `now`;
  `StreamingChatWorkflow.Builder.WithTimeProvider` (unknown-tool reports); and a `timeProvider` on
  `WithCallTimeout`, which times each attempt. A `WorkflowRunner`'s `TimeProvider`
  now also stamps job history and every event its stream yields. Each defaults to
  `TimeProvider.System`.
- **A plan step can hand back what it found, and propose by calling.** `PlanNodeReport.Findings` —
  each a `NodeFinding`, a `Claim` and the `Source` it can be checked against — reaches `NodeOutcome`,
  the node's `NodeReading` and `PlanNodeReported`; a finding with no source is refused and retried
  like a malformed candidate. `PlanNodeAgentOptions.OperationsAsTools` offers each catalog operation
  as a tool: a call is the step's candidate and ends its job, with no report asked for after it, and
  what the model wrote with the call is its summary. Both are opt-in by use, and the plan tier stays
  experimental.
- **A plan step is asked for what it answers.** `PlanNodeAgentRunner<TAnswer>` and
  `PlanNodeAgentOptions<TAnswer>` run a node against any `IPlanNodeAnswer` — the answer's type sets the
  schema, its `Instructions` the turn prompt, its `ToOutcome` what the executor records.
  `PlanNodeFindings` is an answer with only a `Summary` and `Findings`, for a step that changes nothing.
  `PlanNodeAgentRunner` and `PlanNodeAgentOptions` are unchanged in use; they are now the
  `PlanNodeReport` case.
- `AgentJob.Builder.WithAnswerFromText(read)` takes a job's answer from its turn's last text instead
  of asking the model for it again as JSON: no schema is sent and no call follows the tool loop. For
  an answer the turn already gives in words, such as a plan step's summary of what it proposed.
- **A reply that repeats itself ends the run.** An agent job checks a reply that stopped at the output
  limit — or whose adapter does not say why it stopped — for its end repeating one passage over and
  over, and throws `RepeatedOutputException`; `RepeatedOutput.Add` does the same on a stream as it
  arrives, so a caller that streams stops the call. A reply the model ended itself is not checked,
  whatever its last lines look like. `TerminalProviderError.Is` reads the exception as terminal, so it
  is never retried: the job, the plan step and the supervisor's seats end as they do for a depleted
  account, and so does a job whose tool called a model that repeated itself. A reply that only ran long
  is not affected. Every adapter in Ananke sets `AgentResponse.StopReason`, `A2AAgentModel` included
  (`EndTurn` for a message or a completed task). ⚠ A custom `IAgentModel` that leaves it `Unknown` has
  every reply checked, so a reply asked to repeat rows can end the run: set `StopReason`.
- **A time limit per model call.** `model.WithCallTimeout(limit, attempts: 2)` holds every call to
  `limit`: an attempt past it is asked again, and a call past it on its last attempt throws
  `CallTimeoutException`. `TerminalProviderError.Is` reads it as terminal, so neither the engine nor
  a plan retries it further and the run ends. Set the limit where each model is chosen: a short one
  for the model that does small steps, a longer one for the model that reasons. A stream is asked
  again only if it had sent nothing yet. A timeout in a model that a tool calls ends the run too,
  rather than reaching the outer model as a tool error.
- **An answer read as a stream.** `model.Streamed()` asks a model that streams for each answer as a
  stream and hands it back whole, so the client's network timeout applies to each read rather than to
  the whole answer, and feeds each piece to `RepeatedOutput`, so a reply that repeats itself is stopped
  as it arrives. A model that cannot stream is asked as it is. A request that offers tools, answered
  by a stream that ends without a completed response, throws `InvalidOperationException`: a tool call
  arrives only on the completed response.
- **A call's usage says what it spent reasoning, what it read from cache, and what it cost.**
  `TokenUsage.ReasoningTokens`, `TokenUsage.CachedInputTokens` and `TokenUsage.Cost` are what the
  provider reports, and `null` when it reports none. `Cost` is never worked out from rates. The OpenAI
  adapter maps all three, on both paths: reasoning and cached input tokens from the SDK, and the `cost`
  an endpoint such as OpenRouter puts in the usage. `Add` sums each where both sides carry it.
- **A tool can end the turn, and a job can stop rounds that only repeat.** A tool marked
  `ToolBuilder.EndsTurn()` ends the turn once called without error, and the model is asked to answer.
  `WithMaxRepeatedToolRounds(n)`, on `AgentJob` and `TextAgentJob`, answers a call repeating one already
  answered in the turn with a note saying so. After `n` rounds of nothing else it throws
  `RepeatedOutputException`, which ends the run. A repeat whose earlier answer a context strategy left
  out of the last request is answered again, and does not count. Both are off unless set; a plan
  step's operation tools are marked to end the turn. A model that goes on calling tools after its turn
  ended, and again when asked to answer without them, fails the job with a message that says so.
- **Fields of an endpoint's own on a request.** `OpenAIChatAgentModel.WithRequestFields(fields)` writes
  fields by name on every request a model makes, such as OpenRouter's `provider` and `session_id`.
  `AgentRequest.RequestFields` carries them for one request, and `AgentJob.Builder.WithRequestFields` for
  every request a job makes; a request's are written after its model's. The Gemini, Anthropic and A2A
  adapters refuse a request carrying any, naming them. Experimental, as `ANNKEEXP003`.
- **A plan step's finding carries what it quotes**, as `NodeFinding.Quotes`, and an operation's argument
  can be a list of records (`OperationDefinition.Lists`, `ToolBuilder.ParamList<T>`), offered to a step
  calling it as an array.
- **A plan step names how hard it reasons.** `effort:` on a step in a plan file is `PlanNode.Effort`,
  kept through export and a change of plan. `PlanNodeAgentOptions.EffortFields` writes it into each of the
  step's requests, such as OpenRouter's `reasoning`. A step naming an effort, run with no `EffortFields`,
  is refused before any call.
- **A plan step names what it touches.** `touches:` on a step in a plan file is `PlanNode.Touches`: what
  the step may change, as the domain names it, kept through export and a change of plan, and set by a
  Planner's `AuthoredStep.Touches`. Nothing in the plan tier reads it; an applier reads it off the node
  to place and confine what the step proposes.
- **A plan step that proposes by calling can answer in words alone.** `PlanNodeProposal` is a `Summary`:
  what the step wrote with its call, which is its candidate, or, when it called nothing, its last words —
  never asked for again as JSON. An answer gives `IPlanNodeAnswer.FromText` to be read that way; it is
  `null` by default. An answer with no slot for an operation says `IPlanNodeAnswer.RequiresOperationsAsTools`,
  and its runner refuses options without `Operations` and `OperationsAsTools`, where no step could propose.
- **A plan step that reports findings can give them by calling.** With
  `PlanNodeAgentOptions.AnswerAsTool`, `PlanNodeFindings` is also offered as a tool, `report_findings`,
  whose parameters are its `Summary` and `Findings`: a call is the step's answer and ends its job, and
  no answer is asked for after it. Without it, a step with tools that answers in words is asked for the
  same answer again as JSON, in one more call sent without the tools, which a provider's prompt cache
  does not hold. A call whose findings cannot be read is answered with why, and the step goes on. An
  answer offers its tool through `IPlanNodeAnswer.Tool`, `null` by default, and a runner whose answer
  has none refuses the option. Off by default.
- **The advisor may ask a halted step to try again, once.** When the step that stopped left no options,
  `AgentPlanAdvisor` may offer a `PlanOption` whose `Answer` is a line of its own; taken through
  `PlanChoiceJob`, it is recorded on the step against what stopped it, no version is minted, and the next
  pass attempts the step reading it. A step already answered is not offered it again. Each field of the
  options the advisor fills now carries a description in its schema.
- **A proposal says what the halt is.** `PlanProposal.Summary`, and `PlanProposalOffered.Summary`: what
  kind of problem the supervisor says the halt is, citing the finding, and why nothing would help when
  it offers nothing. The narrator writes it under the halt as `says:`.
- **An MCP tool type's tools, in-process.** `toolkit.AddMcpServerTools(instance)` adds each
  `[McpServerTool]` method of an MCP tool type as a tool, declared as the SDK declares it for a server and
  run in this process, with no server or transport between. Its answer is read as a client of that
  server reads it: a `CallToolResult` with `IsError` is an error result, and each text block is a line.
- `AddMcpServerToolsAsync` and `AddMcpPoolAsync` read a parameter whose schema type is a list — an
  optional one, `["string", "null"]` — as its type that is not null. They threw on it.
- **A tool call's content is opt-in.** `Workflow<TState>.RecordContent(bool)` and
  `OrchestrationOptions.RecordContent(bool)`, off by default, put a tool call's arguments and result
  on `AgentToolCalled`; a sub-workflow follows its parent. What the model is sent is the same either
  way. `PlanNarrator` writes a call without content as its tool and result length.
- `AgentToolCalled` is built only when a sink is attached, so a run under `RunAsync` with no sink
  pays nothing for it.
- **`[Redact]` marks personal data on your own types** (`RedactAttribute`, in `Ananke.Abstractions`).
  With content on, a marked property of a `ToolBuilder.ParamList<T>` record or a `ToolResult.Json<T>`
  result is recorded on `AgentToolCalled` as `[redacted]` (`Redaction.Marker`), the result masked
  whole before its cut to `ResultCap`. The tool and the model still get the value. For JSON a host
  writes itself, `Redaction.Masking(options)` gives serializer options that write each marked
  property as the marker, and `Redaction.Mask(json, members)` masks JSON text whose members' types
  are given by name. Text with no type, such as a result from `ToolResult.Ok`, is recorded as written.
- **`AnankeJson.Record`**, for a sink that writes a run's events: the serializer's default names,
  with each marked property written as `[redacted]`, so the workflow's state on `StateUpdated<TState>`
  and the other events is masked. `JsonLinesEventSink` writes with it; its output keeps its shape.
  For writing only, never for a checkpoint.
- **A tool call's event names the call.** `AgentToolCalled` carries `CallId`, the id the model gave
  the call and its result is sent back under; `Round`, the tool round it was made in, counted from 1;
  and `Duration`, measured with the job's `WithTimeProvider` clock from reading the call's arguments
  to having its result.
- **A tool call's span takes the OpenTelemetry GenAI names.** It carries `gen_ai.operation.name`
  (`execute_tool`), `gen_ai.tool.name`, `gen_ai.tool.call.id` — the same id as the event's `CallId` —
  and `error.type` (`_OTHER`) when the tool returned an error. A registered tool's span carries
  `tool.execution_mode` (`local`, `callback`, `mcp`, `openapi` or `platformnative`), and a tool with an
  absolute endpoint carries `tool.target`, the endpoint's host only: never its path or query, which
  can hold a key. The span's existing `tool.*` attributes stay.
- `ISpan.SetAttribute(string, long)` and `ISpan.SetAttribute(string, bool)`. Their default
  implementations format the value and call the string overload, so an existing `ISpan` keeps
  compiling and keeps receiving strings; `ActivitySourceTracer` overrides both and keeps the type.

## Removed

Every published version of each package stays on nuget.org, marked deprecated, and gets no further
releases. They are unlisted at 1.0; a restore that names a version keeps working.

## Upgrading

- ⚠ **`SlidingWindowChunker` keeps every chunk within its window.** A paragraph longer than the window used to be one
  chunk (14,000 characters on a news corpus, past what an embedder reads); it is now split at sentence ends, and a
  sentence longer than the window at spaces. The overlap is the previous chunk's last characters, from the start of a
  word, at most a quarter of the window; it used to be whole trailing paragraphs, which could double a chunk. Chunks
  change, so re-index to get the new ones.

- ⚠ **`MarkdownExtractor` reads YAML front matter as the document's metadata.** A document that opens with
  `---` front matter used to get it as its first sections (an empty one, then the front matter read as a
  heading); now its fields are in `ExtractedDocument.Metadata` and the sections start after it. Chunks of
  such documents change, and `title` comes from the front matter when there is no heading.
- **`KnowledgeCatalogTools.Create` has a third tool, `list_documents`.** An agent given the toolkit sees it
  beside `browse_catalog` and `discover_sources`; it lists nothing until ingestion keeps header fields
  (`DocumentHeaderOptions.Fields`). The Postgres catalog adds a `fields` column to a table made before.
- ⚠ **A knowledge store searches in the mode it is asked for, or refuses it.** `SearchOptions.Mode` used to
  be ignored: every search was by embedding. `InMemoryKnowledgeStore` now does `Sparse` and `Hybrid` (above),
  and `QdrantKnowledgeStore` throws `NotSupportedException` for them. A caller that set either mode against
  Qdrant sets `Dense`, which is what it was getting.
- ⚠ **A tool that throws reaches the model as an error result** — `Tool 'x' failed: <message>` — and
  the job goes on; it used to fail the job. Cancellation, a `GuardrailException`, an interrupted
  sub-flow, and a `CallTimeoutException` or `RepeatedOutputException` from a model the tool called
  still end it.
- ⚠ **A job runs up to 10 tool rounds by default**, up from 3 (`AgentJobFactory.DefaultMaxToolRounds`),
  and at the limit it gets one more call, asked to answer without tools, before it throws. A workflow
  manifest or host snapshot that names no `max_tool_rounds` means 10 too; `AgentRouter`'s default stays
  3. The chat workflow, at its limit, ends with *"I could not finish within the tool-call limit."*,
  streamed like any reply.
- ⚠ **A structured reply in a code fence, or after a sentence of preamble, is read.** One that still
  does not parse gets one repair round, compacted and held to `WithContextLimit` as the first attempt
  is, and then throws `JsonException`.
- ⚠ **Memory keeps the framework's own prompts out.** An agent job and `StreamingChatWorkflow` no longer
  store their coercion and repair prompts, or the prompts sent at the tool-call limit, at a turn a
  tool ended, and after a permanent tool error, in `IConversationMemory`: a stored history has only
  what was said.
- ⚠ **Every `CachingAgentModel` key changes once.** A request's fields of its own are part of the key, so
  an entry cached by an earlier version is not found, and its call is made again.
- ⚠ `ChatSession.EmitAsync` and `StreamAsync` throw `InvalidOperationException` before `BindResponse`;
  events emitted then used to vanish.
- ⚠ **`OpenAIChatAgentModel.Create` with an `AuthenticationPolicy` or `AuthenticationTokenProvider` is
  `[Experimental]`, as `ANNKEEXP002`**: both build the OpenAI SDK's `ChatClient` through constructors
  the SDK marks `OPENAI001`. Add the id to `NoWarn` to keep using them.
- ⚠ **`RedisConversationMemory` no longer hides a Redis failure.** `AddAsync`, `ClearAsync` and
  `GetHistoryAsync` log and rethrow; a failed read used to answer an empty history, which reads as a
  new conversation. One entry that will not deserialize is still skipped with a warning.
- `OpenAIChatAgentModel.GenerateAsync` reads tool calls whatever the `finish_reason`, as streaming
  already did — so an OpenAI-compatible server that finishes a tool call with `stop` (Ollama) is no
  longer read as plain text.
- ⚠ **A job no longer retries a plain 429.** The provider's SDK already retries it, so the job's own
  retries multiplied every request — up to 12 per call on OpenAI. `DefaultShouldRetry` now retries a
  429 only when its error states how long to wait. `GeminiAgentModel.Create` and
  `CreateAgentPlatform` turn on the Gemini SDK's retries (3 attempts), which were off. A
  `GeminiAgentModel` built on your own `Client` retries only if its `HttpOptions` carry `RetryOptions`.
  `A2AAgentModel` retries a 429 itself (3 attempts, honouring `Retry-After`) through the new
  `RateLimitRetryHandler`; an `HttpClient` you pass in `A2AAgentModelOptions` retries only if you add
  the handler to it. A custom `IAgentModel` with no retry of its own is not retried on a plain 429:
  wrap it in `ResilientAgentModel`.
- ⚠ **A structured reply cut off at the output-token limit throws `InvalidOperationException`**
  saying so, instead of a `JsonException`, and no repair round is spent on it.
- ⚠ **`AnthropicAgentModel`'s default `maxTokens` is 16384**, up from 4096, which cut off long
  replies. Pass `maxTokens` to keep the old limit.
- ⚠ **Claude Opus 5, Sonnet 5 and Fable 5 are Legacy**, replaced by `Opus55`, `Sonnet55` and
  `Fable51`; still valid, with no warning. `Models.Anthropic.Starred` is `Sonnet55`, and
  `AnthropicAgentModel`'s default `model` is `Models.Anthropic.Starred`, which was `Sonnet5`. Pass
  `model` to keep the old one. `Models.OpenAI.Starred` is `Gpt56Luna`, which was `Gpt56Terra`, so
  `nnke new` scaffolds Luna and Sonnet 5.5.
- ⚠ **`IdleCellPrunePolicy` prunes idle cells.** `WorkflowExecutionMonitor`'s health snapshots now
  carry `LastRequestAt` (the latest execution) and `ObservedSince` (the first one recorded); both were
  unset, so every cell read as idle for no time and was never pruned. A host with the policy wired
  now removes cells idle past its threshold.
- ⚠ **A call through a cost-resolving router is charged once.** In a workflow that also sets flat
  rates, a routed call's tokens were priced again at the flat rate on top of the router's cost, so a
  budget stopped early. It is now charged its routed cost only, and a router called outside an agent
  job (a summarizer, an approval gate) still adds its cost without touching other jobs' spend.
  `UsageRecord` gains an optional `Priced` parameter for this; a custom `IUsageRecorder` should
  leave a priced record's tokens out of `UncostedUsage`.
- ⚠ **A budget holds across a pause.** A run resumed after an interrupt used to start its spend from
  zero, so each leg had the whole budget. Checkpoints now carry `RunCost` and `RunUsage`, and a resumed
  run counts them. A checkpoint written by 0.9.0 has neither, and resumes from zero as before.
- ⚠ **The plan tier is `[Experimental]`, as `ANNKEEXP001`.** Code that uses
  `Ananke.Orchestration.Planning`, `Workflow.Supervise`, `AgenticPattern.SupervisedPlan`, or the plan
  types in `Ananke.Design` and `Ananke.Organics` no longer compiles until it suppresses the id — add
  `<NoWarn>$(NoWarn);ANNKEEXP001</NoWarn>` to the project. The marking says the API may change in any
  release, and this one changes it too (*Breaking changes*). `docs/reference/experimental-apis.md`
  lists what it covers.
- ⚠ **Qdrant search runs through the Query API** (`QueryAsync`), which needs a Qdrant server at 1.10 or
  later.
- ⚠ **Every consumer of `StreamAsync` stops receiving a tool call's arguments and result**:
  `AgentToolCalled.Arguments` and `Result` are `null` unless the workflow calls
  `RecordContent(true)`, or the registered runner was configured with
  `OrchestrationOptions.RecordContent(true)`. A call with no arguments is still an empty string when
  content is on. `ResultLength`, `IsError`, `CallId`, `Round` and `Duration` are always set.
- ⚠ **A tool call's span is named `execute_tool {tool}`**, not `tool:{tool}`. A dashboard, query or
  sampler that matches the old name matches nothing.
- ⚠ **A tool call's span sends numbers and flags as typed values** through `ActivitySourceTracer`:
  `tool_round`, `output_length` and `tool.output_chars_after` as integers, and `tool.error`,
  `tool.retryable`, `tool.malformed_arguments`, `tool.hallucination`, `tool.output_capped` and
  `tool.output_recoverable` as booleans. A query that compares them to the strings `"1"` or `"true"`
  stops matching.
- `AddMcpPoolAsync`'s tools join a result's text blocks one per line, as `AddMcpServerToolsAsync`'s do;
  they ran them together. Both read a result's structured content when it has no text.
- `nnke serve`'s FED061 hint and `PlatformDivisionApprovalGate`'s rejection message no longer point
  at the removed CLI.
- `JsonFileDeploymentRegistry`'s cross-process lock has a new name. A 0.9.0 process and a 0.9.1
  process writing the same registry file at the same time no longer exclude each other.
- `TimeDecay.ComputeWeight` and `TimeDecay.Apply` without a `now` are `[Obsolete]`: they read the
  system clock. Pass `now` from a `TimeProvider`.

## Breaking changes

Every package under *Removed* is gone from this release: a project that references one fails to
restore against 0.9.1.

`OpenTelemetryBudgetMeter` listens to the usage instruments above instead of
`ananke.federation.tokens.in`, `.tokens.out` and `ananke.federation.usd`, which nothing in Ananke
published. `AnankeSourceNames.Federation` and `Sources.Federation` are removed. A host that published
the old names itself publishes the new ones, or reads the framework's.

Constructors, `EmpiricalMemoryTools.Create` and `DivisionApproval`'s factories that gained an optional
`TimeProvider` (above) keep compiling unchanged, but code compiled against 0.9.0 that calls them must
be rebuilt.

`NodeRejection.Candidate` is nullable: a rejection can now be of findings rather than of a candidate.
Code that reads `Candidate` without a null check gains a nullable warning.

`PlanNodeReport.Done` is `required`: code that builds a report names it, and a model reply that leaves
it out no longer reads as done — the reply fails to parse and gets the repair round.

`ChildSpec.TargetPlatform` is removed. It named a platform for a divided cell to run on, and no host
in Ananke reads it once `Ananke.Federation` is gone. Delete the assignment; a child runs on the host
that `IWorkflowDivider` was given.

`AgentToolCalled.CallId`, `Round` and `Duration` are `required`: code that builds an
`AgentToolCalled` itself, such as a test, sets them.

`AgentToolCalled.Arguments` and `Result` are `string?`. Code that reads them without a null check
gains a nullable warning.

`TraceInfo` gains `RecordContent`, and `WorkflowRunner`'s constructor a `recordContent` parameter,
both last and optional: source keeps compiling, and code compiled against 0.9.0 that calls them must
be rebuilt.
