# Ananke v0.7.0

**Theme: agent-friendly CLI tooling — `nnke` grows from a scaffold helper into a full design-time companion for humans and AI coding tools.**

Three capability pillars land in this release:

- **`nnke` CLI expansion** — six new commands (`inspect`, `explain`, `patterns`, `docs`, `mcp-server`, `schema`) plus a global `--json` flag turn `nnke` into a machine-readable tool that AI assistants can call directly during development.
- **MCP server mode** — `nnke mcp-server` exposes every CLI capability as an MCP tool over stdio JSON-RPC, enabling Claude Desktop, VS Code Copilot, Cursor, and any other MCP client to inspect projects, search docs, explain errors, and list patterns without leaving the editor.
- **`WorkflowTopologyExporter`** — new `Ananke.Design` type that round-trips a code-first `WorkflowDefinition<TState>` to DSL connection lines or a `.ananke.yml` manifest skeleton, bridging the code-first and design-first worlds.

## What's new

### `nnke` CLI — six new commands

The `nnke` .NET global tool gains six commands on top of the existing `new` / `validate` / `diagram` trio. Every command accepts a `--json` flag (new global option) for machine-readable output.

#### `nnke inspect [dir]`

Analyzes an Ananke project directory and produces a health report covering manifest validity, topology, NuGet dependency state, provider configuration, and detected patterns.

```
$ nnke inspect ./MyWorkflow
  Manifest     ✓ expense-analyzer.ananke.yml
  Topology     ✓ 4 jobs, 3 connections, terminal reachable
  NuGet        ✓ Ananke.Orchestration 0.7.0
  Provider     ✓ openai configured (secrets.json)
  Pattern      ✓ etl detected
```

With `--json` the report becomes structured JSON — suitable for automated diagnostics and agent self-inspection (`ananke_inspect` MCP tool).

#### `nnke explain [code]`

Shows a full explanation for any `ANANKE_*` diagnostic code: title, description, bad example, corrected example, and fix steps. Omit the code to list every known code.

```
$ nnke explain ANANKE_TOPO_003
  ANANKE_TOPO_003 — Fork without matching join
  A fork connection splits execution into parallel branches that never merge.
  ...
```

#### `nnke patterns [pattern]`

Lists the full pattern catalog or describes a single pattern. Patterns are grouped into manifest-driven (expressed in `.ananke.yml`) and code-driven (built via `AgenticPattern` or `Workflow<T>` primitives).

```
$ nnke patterns
  Manifest patterns: etl, fan-out, sequential, sub-workflow
  Code patterns:     handoff, human-in-the-loop, iterative-refinement, review-critique, router

$ nnke patterns review-critique
  Review & Critique — code-driven agentic pattern
  Topology: draft → review → (critique | accept) → …
  ...
```

#### `nnke docs [topic] [--list] [--search <terms>]`

Browses the Ananke documentation from the terminal. Reads guides from the repository `docs/` directory (located by walking up from CWD to find `Ananke.slnx`).

```bash
nnke docs --list                         # list all topics
nnke docs getting-started                # read a guide
nnke docs --search "interrupt human"     # full-text search
nnke docs --search "fork join" --json    # structured results for agents
```

#### `nnke mcp-server`

Launches `nnke` as a stdio MCP server, exposing all commands as MCP tools that any MCP client can call. No network ports, no HTTP — a local process launched by the client over stdin/stdout (JSON-RPC).

| MCP Tool | Equivalent CLI |
|---|---|
| `ananke_docs_search` | `nnke docs --search <q>` |
| `ananke_docs_read` | `nnke docs <topic>` |
| `ananke_docs_list` | `nnke docs --list` |
| `ananke_inspect` | `nnke inspect [dir]` |
| `ananke_explain` | `nnke explain <code>` |
| `ananke_explain_list` | `nnke explain` |
| `ananke_patterns_list` | `nnke patterns` |
| `ananke_patterns_describe` | `nnke patterns <pattern>` |
| `ananke_validate` | `nnke validate <file>` |

Add to Claude Desktop (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "ananke": {
      "command": "nnke",
      "args": ["mcp-server"]
    }
  }
}
```

A pre-configured `src/.vscode/mcp.json` is included for VS Code Copilot (runs from source via `dotnet run`).

#### `nnke schema`

Emits a JSON description of every command, its arguments, and its options. Designed for LLM agents to discover `nnke` capabilities programmatically without reading documentation.

```bash
nnke schema | jq '.commands[].name'
```

### `WorkflowTopologyExporter` — code-first → design-first bridge (`Ananke.Design`)

`WorkflowTopologyExporter` exports a built `WorkflowDefinition<TState>` back to DSL text and/or a `.ananke.yml` manifest skeleton.

```csharp
var definition = new Workflow<ExpenseState>("expense-analyzer")
    .Job("extract",  extractFunc,  out var extract)
    .Job("analyze",  analyzeAgent, out var analyze)
    .Job("review",   reviewAgent,  out var review)
    .Then(extract, analyze)
    .Then(analyze, review)
    .Then(review, Workflow.EndRef)
    .Build();

// Export to DSL
string dsl = WorkflowTopologyExporter.ExportDsl(definition);
// extract -> analyze
// analyze -> review
// review -> End

// Export to manifest skeleton
string yaml = WorkflowTopologyExporter.ExportManifest(definition);
```

**Export fidelity:**

| Connection type | Fidelity |
|---|---|
| Direct, Fork, Join | Lossless — round-trips perfectly |
| Loop | Structural — `Until` predicate not serializable; exported as `# loop` annotation with `max_iterations` |
| Router | Structural — router logic is opaque; exported as `router(…)` with option names |
| Interrupt | Lossless — exported as `interrupt(name)` |

### `SelfImprovingWorkflowDemo` (new demo)

A new demo (`demos/SelfImprovingWorkflowDemo`) shows a workflow that diagnoses its own missing capability using introspection tools — no API keys required.

The scenario: a travel expense analyzer processes reports containing foreign currencies (GBP, EUR, JPY) but the initial workflow has no conversion step. An overseer agent detects the gap via three tools that mirror `nnke` commands:

| Tool | Mirrors |
|---|---|
| `inspect_workflow` | `nnke inspect` |
| `search_docs` | `nnke docs --search` |
| `suggest_fix` | `nnke explain` |

Run 1 (v1 manifest) — the overseer identifies the missing `convert_currencies` job and recommends adding it. Run 2 (v2 manifest) — the fixed workflow normalizes all amounts to USD before the `analyze` agent runs. Both runs use `SimulatedModel` for offline execution.

### Documentation improvements

- **`docs/faq/`** — monolithic `docs/faq.md` (800+ lines) split into six focused topic files: `general`, `integration`, `memory`, `operations`, `providers`, `workflows`. The site renders them as a tabbed section.
- **`llms.txt` / `llms-full.txt`** — standard `llms.txt` manifest (per the [llms.txt convention](https://llmstxt.org)) in the repo root, listing all guides and reference pages with one-line descriptions for LLM consumption.
- **Guide 00 — `nnke` Tool Companion** — new guide covering installation, every command with examples, the `--json` flag, and MCP server setup for Claude and Copilot.
