# Ananke v0.8.5

**Theme: architecture boundary correction**

The changes are either boundary hygiene (no public API effect) or well-contained breaking moves to `Ananke.Abstractions` that require `using`-directive updates only.

---

## What's new

### Boundary fix: cross-cutting contracts lifted to `Ananke.Abstractions`

The root cause behind two documented dependency inversions (`OpenTelemetry→Organics` and `Qdrant→Organics`) was that cost-accounting and sensing contracts lived inside `Ananke.Organics`. The fix is a targeted relocation:

- `IBudgetMeter`, `BudgetSpend`, and `InMemoryBudgetMeter` moved from `Ananke.Organics.Division.Approval` to `Ananke.Abstractions.Budget`.
- `IDomainRouter` moved from `Ananke.Organics.Sensing` to `Ananke.Abstractions.Agents`.
- `Ananke.Organics` now re-exports these via `global using` aliases so existing code inside the package compiles without changes.
- `Ananke.OpenTelemetry` (`OpenTelemetryBudgetMeter`) and `Ananke.Qdrant` (`QdrantDomainRouter`) are updated to reference the new locations and drop their `Organics` project references, restoring the documented layering.

The `OTel→Organics` and `Qdrant→Organics` edges are gone.

### Boundary fix: provider adapters are now Abstractions-only

`ARCHITECTURE.md` presented `Ananke.Orchestration.{Anthropic,Google,OpenAI}` as thin adapters that depend only on `Ananke.Abstractions`. In practice all three referenced `Ananke.Orchestration` for translation and credential contracts. This release makes the documented principle true:

**New namespace in `Ananke.Abstractions.Providers`:**

| Type | Notes |
|---|---|
| `ICredentialProvider` | Moved from `Ananke.Orchestration.Credentials` |
| `IModelMapper` + `ModelCapabilityFlags` | Moved from `Ananke.Orchestration.Translators` |
| `ISystemPromptCompiler` | Moved from `Ananke.Orchestration.Translators` |
| `IJsonSchemaTranslator` | Moved from `Ananke.Orchestration.Translators` |
| `IToolSchemaTranslator` | Moved; **signature changed** — see Breaking changes |
| `SystemPromptBuilder` (with `Default` and `PassThroughJsonSchemaTranslator`) | Moved from `Ananke.Orchestration.Translators` |
| `ToolExecutionMode` | Moved from `Ananke.Orchestration.Tools` |
| `ProviderTool` | New record — schema-only projection of a tool for use with `IToolSchemaTranslator` |

`ToolDefinition` gains a `ToProviderTool()` convenience method that projects name, description, parameters schema, execution mode, and platform capability into a `ProviderTool`. `Ananke.Orchestration.Anthropic`, `Ananke.Orchestration.Google`, and `Ananke.Orchestration.OpenAI` now each reference only `Ananke.Abstractions`; the `ProjectReference` to `Ananke.Orchestration` has been removed from all three.

### `AnankeBuilder` and `StudioHostBuilder`: `TryAddSingleton` for in-memory defaults

The two main composition roots (`Ananke.AspNetCore/DependencyInjection/AnankeBuilder` and `Ananke.Roles/Studio/StudioHostBuilder`) previously registered `InMemoryCapabilityMap`, `InMemoryMeshAggregator`, and `InMemoryLineageStore` as unconditional `AddSingleton`, silently overriding any user-supplied store. They now use `TryAddSingleton` so a user-registered implementation always wins. This aligns with the pattern already used in `Ananke.Orchestration` and `Ananke.StateMachine`.

### `ColonyGraphBuilder` projection made async

`Ananke.Organics/Topology/ColonyGraphBuilder` was blocking the thread pool with `.GetAwaiter().GetResult()` calls to `graph.UpsertNodeAsync` and `graph.UpsertEdgeAsync` inside a synchronous loop — the only genuine sync-over-async site found in the production tree. The projection method is now `async` and properly awaits both upsert calls.

### `DateTime.UtcNow` replaced with injected `TimeProvider`

Three remaining production sites that bypassed the project-mandated `TimeProvider` have been fixed:

- `Ananke.Platforms/StreamingMessageBridge` — flush-throttle timestamps
- `Ananke.Redis/RedisCheckpointStore` — TTL computation
- `Ananke.StateMachine/Middleware/ITransitionMiddleware` — timing in a default interface method

### Silent `catch {}` fixed in Discord adapter

`Ananke.Platforms.Discord/DiscordAdapter` had a catch-variable scope collision (CS0136) that was also swallowing the original exception silently. The inner catch variable is renamed and the catch is narrowed to `OperationCanceledException` for the expected interaction-expiry path.

### `ARCHITECTURE.md` dependency graph updated

The documented dependency graph now matches the real `.csproj` edges after all boundary moves. Previously omitted edges (`OpenTelemetry→Organics`, `Qdrant→Organics`, `providers→Orchestration`) have been corrected to reflect the post-0.8.5 state, and the provider adapter layer is shown correctly as `providers → Abstractions` only.

### V2 harness M2 — trajectory capture and hallucination detection

Building on the harness roadmap (`ADR-arch-018`), M2 delivers the trajectory and observation layer:

- `ITrajectoryObserver` (Abstractions) + `TrajectorySnapshot` + `TrajectorySnapshotBuilder` (Orchestration) — structured, per-step trajectory capture during `TextAgentJob` execution.
- `IHallucinationObserver` + `HallucinatedToolCallEvent` (Abstractions) — detection interface for tool calls the model fabricates outside the registered `ToolKit`.
- `IWorkflowTracer` added to `Ananke.Abstractions` for cross-cutting workflow span instrumentation.
- `ChannelTrajectoryObserver` — `Channel<T>`-backed async dispatch, decouples trajectory recording from the critical execution path.
- `ToolMetrics` in `Ananke.Orchestration.Tools` — per-tool call counters and timing helpers.
- Tests: `TrajectorySnapshotTests`, `HallucinationDetectionTests`, `RecoveryClassificationTests`.

### V2 harness M4 — adaptive harness policy

M4 delivers the composable policy engine that governs when and how the harness triggers a learning cycle:

- `IAdaptiveHarnessPolicy` (Abstractions) + `AdaptiveHarnessOptions` — contract and configuration for harness adaptation decisions.
- `ILearningCycleTrigger` (Abstractions) — decoupled trigger interface for offline learning runs.
- `CompositeAdaptiveHarnessPolicy` (Orchestration) — pipeline of policies evaluated in order; short-circuits on the first conclusive decision.
- `AdaptationQueueWorker` — background worker that drains the adaptation queue and invokes the policy chain.
- DI registration: `AddAdaptiveHarness(options)` extension on `IServiceCollection`.
- Tests: `AdaptivePolicyEndToEndTests`, `CompositeAdaptivePolicyTests`.

### V2 harness M1/M3 — federation workflow host rework

`ClaudeWorkflowHost`, `AzureWorkflowHost`, and `VertexAIWorkflowHost` were large monolithic files duplicating platform-specific wiring. They have been refactored against `PlatformWorkflowHostBase`, which now handles the shared lifecycle (deploy → run → teardown) and error propagation. The platform-specific overrides are significantly smaller.

### Test coverage expanded

- `Ananke.Abstractions.Tests` — `AgentMessageTests` (414 lines) covering the full normalized agent message model.
- `Ananke.Abstractions.Tests` — `InMemoryBudgetMeterTests` (222 lines) for the moved budget meter.
- `Ananke.StateMachine.Tests` — `StateMachineChannelWorkerTests` (203 lines) bringing the previously 0%-covered state machine worker under test.

## Breaking changes

### `IToolSchemaTranslator.Translate()` — signature changed

```csharp
// Before
object Translate(IEnumerable<ToolDefinition> tools);

// After
object Translate(IEnumerable<ProviderTool> tools);
```

**Who is affected:** anyone who implements `IToolSchemaTranslator` directly (custom provider packages), or who calls `Translate()` with a `ToolDefinition` collection.

**Migration:** call `ToolDefinition.ToProviderTool()` at call sites before passing to `Translate()`. The built-in translators (`AnthropicToolSchemaTranslator`, `GeminiToolSchemaTranslator`, `OpenAIToolSchemaTranslator`) are already updated. The Federation deployers (`ClaudeDeployer`, `VertexAIDeployer`) now call `.Select(t => t.ToProviderTool())` before translating.

### Provider translation and credential types — namespace change

The following types moved from `Ananke.Orchestration.*` to `Ananke.Abstractions.Providers`:

| Type | Old namespace | New namespace |
|---|---|---|
| `ICredentialProvider` | `Ananke.Orchestration.Credentials` | `Ananke.Abstractions.Providers` |
| `IModelMapper` | `Ananke.Orchestration.Translators` | `Ananke.Abstractions.Providers` |
| `ModelCapabilityFlags` | `Ananke.Orchestration.Translators` | `Ananke.Abstractions.Providers` |
| `ISystemPromptCompiler` | `Ananke.Orchestration.Translators` | `Ananke.Abstractions.Providers` |
| `IJsonSchemaTranslator` | `Ananke.Orchestration.Translators` | `Ananke.Abstractions.Providers` |
| `IToolSchemaTranslator` | `Ananke.Orchestration.Translators` | `Ananke.Abstractions.Providers` |
| `SystemPromptBuilder` | `Ananke.Orchestration.Translators` | `Ananke.Abstractions.Providers` |
| `ToolExecutionMode` | `Ananke.Orchestration.Tools` | `Ananke.Abstractions.Providers` |

**Migration:** replace `using Ananke.Orchestration.Credentials;`, `using Ananke.Orchestration.Translators;`, and `using Ananke.Orchestration.Tools;` (where used for these types) with `using Ananke.Abstractions.Providers;`.

### Budget and sensing types — namespace change

| Type | Old namespace | New namespace |
|---|---|---|
| `IBudgetMeter` | `Ananke.Organics.Division.Approval` | `Ananke.Abstractions.Budget` |
| `BudgetSpend` | `Ananke.Organics.Division.Approval` | `Ananke.Abstractions.Budget` |
| `InMemoryBudgetMeter` | `Ananke.Organics.Division.Approval` | `Ananke.Abstractions.Budget` |
| `IDomainRouter` | `Ananke.Organics.Sensing` | `Ananke.Abstractions.Agents` |

The old locations in `Ananke.Organics` re-export these via `global using` aliases so code compiled against `Ananke.Organics` directly is source-compatible. Direct consumers of these types with explicit `using Ananke.Organics.*` directives should switch to the new `Ananke.Abstractions` namespaces.
